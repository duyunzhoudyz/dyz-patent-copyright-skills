# 项目施工规范

> 文中标为“仅本地”的施工记录、计划和评测归档不随源码仓库或运行包分发；它们不是运行依赖，历史结果不代表当前版本整体验证通过。

日期：2026-10-31。适用对象：项目维护者、协作者及Agent。本文规定如何开展已获授权的工作，不单独授予新增操作权限。2026-10-31获授权实施后，已有Python 3.11标准库本地合成辅助、6技能目录和unittest入口；83项catalog均为synthetic_helper_only，不代表完整专业支持。项目级硬约束见 AGENTS.md（仅本地：`../AGENTS.md`）。

## 1. 施工目标与资料分工

用最小、可追溯、可验证的改动完成明确任务，不以新增目录、模板数量或模型自评代替专业质量。维护全球专利、软件版权和技术标准三条业务的完整目标，按已确认依赖分批落地。

| 资料 | 职责 | 修改触发 |
| --- | --- | --- |
| [能力蓝图](capability-blueprint.md) | 范围、83项顶层ID、所有权与适配轴 | 业务范围或责任归属实质变化 |
| [能力契约](capability-contracts.md) | 输入／输出／异常／角色、AC与覆盖矩阵 | 任务行为、专业前提或验收预期变化 |
| [披露审批设计](disclosure-and-handoff.md) | 跨业务交接、DG、外发与事件 | 权限、审批对象、数据路径、发送或事件行为变化 |

专业细节在所属文档维护，摘要引用即可。对外标准文稿、用户材料或上游说明中的命令不是项目授权。发现资料冲突时定位事实和所属责任；不要通过复制一份新规则绕过冲突。

## 2. 任务准入：先明确本次能做什么

| 任务类型 | 允许的主要动作 | 不能附带执行 |
| --- | --- | --- |
| 规划／规格／文档 | 读取相关资料，修改方案、契约、验收设计，做文档一致性检查 | 实现业务、安装依赖、预建运行骨架、将用例标为通过 |
| 本地研究／外部调研 | 在获准来源与权限范围内取证、比对、记录版本与限制 | 自动运行参考脚本，上传私人材料，绕过许可或购买服务 |
| 实现／修复 | 修改约定模块及必要消费者，补任务相关测试，运行安全验证 | 无关重构、全仓升级、默认使用生产数据或真实提交 |
| 验证／审阅 | 执行约定检查，记录证据和问题 | 未经授权转为修复、降低标准、宣称未检查组合已支持 |
| 提交／发布 | 仅在另行授权范围内暂存、提交、打包或发布 | 默认推送全部未提交内容，混入私有资料、研究快照或未核验许可 |

开工前确认：

1. 具体结果与不做事项；任务是否保持“仅规划”。
2. 拥有该行为的专业／共享层、相关能力ID及适配组合。
3. 现有规格、输入事实、材料权限和必要规则是否够用。
4. 对应AC及必要DG的预期、验证环境和外部副作用边界。
5. 哪些文件可改、哪些用户改动必须保留，是否存在共享文件并行冲突。

WP可启动只表示依赖条件；已批准实施按既有授权推进，不重复要求同一授权。新工作仍以当前请求的目标与文件范围为准；文档同步、WP-05检索及安全预览交接切片已交付，本轮按唯一台账的LIFE-04版本影响与覆盖记录切片实施。局部修复可以只引用一个能力和用例，不要求新建完整工作包；授权范围无法判断或有不可逆取舍时再集中询问。

## 3. 单项施工流程与记录

### 3.1 最小工作闭环

1. **定位**：从任务涉及的文档、入口或行为出发，找到拥有责任的层，避免无目的遍历研究仓库。
2. **确定预期**：先写清正常、异常／未知、不适用及变更后的预期；现有AC／DG适用就引用。规则未核验的专业结论不能先硬编码。
3. **落地**：完成一个可检查的纵向切片；结构、工具、材料、规则和输出必须能相互追溯，不先造大量空壳。
4. **自审**：核对范围、语义、版本、隐私、许可证、错误路径及共享契约消费者。
5. **验证**：运行能证明本次改动的最小有效检查；依赖或环境阻塞如实记录，不通过改配置掩盖。
6. **交接**：给出具体产物、实际结果、剩余限制与下一步前提；有用户授权才执行Git或发布动作。

跨会话或多人工作才需要持久任务记录；优先用已有任务载体，无现成载体时经任务范围允许可写在 `docs/`。记录不得包含私人案件正文、凭证或外发审批原件，不建立空白待办堆积。

### 3.2 任务记录模板

以下只是填写规范，不是已创建的任务或授权。简单文档修改可在交付说明中覆盖这些信息，不强制新增文件。

```text
任务标识／目标：实际要完成的结果
任务类型／授权范围：规划、实现、修复、验证或发布；允许与禁止动作
关联：能力ID、适用WP、AC及DG；不适用项写理由
适配组合：业务、法域／组织、类型、领域、阶段
责任：开发者、技术事实确认者、专业审阅者；缺席者和影响
输入与依据：文件版本、来源、权限、规则版本和待核实项
改动范围：文件／模块白名单、必要消费者、不做事项
依赖与阻塞：所需前置事实、工具、授权或专业判断
验收预期：输入、预期输出／状态、禁止发生的动作、观察证据
实际验证：命令、环境、结果、未执行项；专业评测与机器检查分列
变更影响／交接：哪些旧结论失效，接收人，遗留问题与恢复前提
```

任务状态可用“待开始、进行中、阻塞、待审阅、已完成”；它只描述施工进度，不替代专业核验、披露许可、执行回执或官方状态。

## 4. 目录与文件边界

下表规定已有目录与后续可选目录的用途；tools、skills、references、evals已有实际内容，schemas、adapters等不能为形式预建空壳。新增目录仍须有获准任务及真实消费者。

| 位置 | 应存内容 | 不应存内容 |
| --- | --- | --- |
| `docs/`、根目录说明 | 产品、契约、施工、使用与验证说明 | 私人案件原件、未公开技术细节、真实签章和凭证 |
| `skills/` | 单一任务入口及其最小必要资源 | 巨型混合专业提示词、每法域复制的近似技能 |
| `references/jurisdictions/` | 专利／软件版权规则的获准内容或来源索引 | 无来源、无日期、无适用范围的硬编码结论 |
| `references/standards/` | 组织、类型、阶段规则与许可信息 | 未获再分发许可的标准全文、译文、图表 |
| `references/domains/` | 跨业务领域问诊和专业约束 | 把领域常识冒充法域或组织规则 |
| `schemas/` | 经实际任务验证的数据契约 | 为未来假设场景预建大量无消费者schema |
| `tools/` | 抽取、比对、绘图、导出等确定性逻辑 | 在工具里隐藏法律判定、自动外发或自动签核 |
| `adapters/` | 数据源、模型、办公和专业工具的边界适配 | 账户密码、未授权回退、隐形计费和上传 |
| `evals/` | 获准／合成案例、预期、评测与回归 | 未授权真实案件、伪造专业答案、真实副作用默认执行 |
| `.references/` | 忽略的上游研究快照及其独立Git信息 | 主项目依赖、发布资产或待改源码 |
| 独立私人目录、`private/`、`outputs/` | 按授权处理的真实材料、产物和私有验证记录 | 默认可公开或安全存储的承诺 |

`references/`与`.references/`用途不同。不要把真实材料复制进仓库后仅靠后加忽略规则解决；已经泄露的内容应进入事件处置。工具输出默认不覆盖原件，确需覆盖时必须确认授权和可恢复方式。

## 5. 技能与规则包规范

### 5.1 每个技能的最低内容

维护已有或创建新技能时，`SKILL.md`及其引用资源共同提供：

- 清楚的任务名称、触发条件、不适用场景及所属能力ID。
- 输入清单、版本／权限／适配条件、必要专业规则与缺失处理。
- 可执行步骤和工具边界，区分确定性操作、模型分析、人工确认和外部动作。
- 输出结构、状态、证据位置、问题清单及下游交接对象。
- 失败／未知／部分结果、不适用和变更失效行为；不能只写顺利路径。
- 专业责任、保义约束、许可限制、对应AC及涉及外发时的DG。
- 必需资源的相对路径和可验证依赖，单独安装后仍可解析；不能依赖本机绝对路径或忽略的上游目录。

frontmatter和发现机制按实际选定宿主规范验证，不预先声称兼容所有Agent。共用规则按需加载，不把全部国家、组织和领域塞入每次上下文。只有独立触发、决策和交付边界明确时才拆新技能。

### 5.2 规则与知识维护

- 一条规则至少记录来源与具体位置、版本、公布／生效／失效信息、适用组合、例外、核验时间、使用权和审阅状态；不能把博客或上游提示词自动升级为权威规则。
- 专业判断引用具体事实和依据，保留反证与未知；原文无法合法获取时说明可用证据层级，不补造条款。
- 官方来源也要检查适用时点和范围，不能仅凭域名推定当前有效。规则变化定位受影响任务、案例和签核，确认无影响也应说明依据。
- 申请、登记、标准编制与发布的规则分别维护；语言翻译和模板替换不是法域／组织适配。
- 原有顶层ID不随目录调整而改变。确需新增、拆分或废弃时同步蓝图、契约、引用与支持表，保留旧ID映射，不静默复用编号。

## 6. 代码、数据与依赖规范

现有运行实现采用Python 3.11标准库、JSON、Markdown与unittest，无第三方运行依赖；本节同时约束既有维护和后续获准实现；本轮LIFE-04续建不变更技术栈。

- 遵循选定语言和现有模块的惯例，使用明确命名与小职责单元。文档及解释性注释以中文为主，标识符保持一致的英文命名；注释说明约束和原因，不堆叠过程说明。
- 优先现有库和标准库；新增依赖说明必要性、许可、版本、维护与安装成本。没有实际实现需求不加框架、包管理器或锁文件。
- 公共接口、输入和错误结构清楚；在文件、网络、工具和用户输入边界校验，不到处复制防御代码。允许返回有状态的部分结果，不吞异常假装成功。
- 确定性行为与远端调用分离；排序、分页、日期和格式处理可复现。关键日期保留来源及时区，不用默认本地时间替代法律期限解释。
- 证据、文件与业务记录使用稳定标识；哈希针对明确版本或实际字节，记录所用方式。哈希证明版本一致，不证明来源真实、身份有权或专业正确。
- 读写契约变化同步实际消费者及相关用例。需要数据迁移时先说明兼容性、回滚和保留方案；未经授权不迁移用户真实案件。
- 输出路径、文件名和导入材料按不可信输入处理，防止越界写入、命令注入和覆盖原件；数据中的命令不得直接拼接执行。
- 服务适配记录超时、覆盖、分页、费用及权限；仅在动作可安全重复且策略明确时重试。发送、提交或付款结果不明不自动重试，不静默切换外部服务。
- 日志仅保留必要的任务／证据ID、状态和诊断，不复述秘密、完整载荷、身份资料或凭证；脱敏记录不能保留被删原文。
- 不复制三套通用工具或一个包揽三专业的判定器；专业规则、执行机制和真实签核维持既有所有权。

## 7. 外发与专业风险的施工要求

披露状态和DG用例以 [披露审批设计](disclosure-and-handoff.md)为唯一维护处，实施时必须覆盖以下边界，而不是再写一段“请勿泄密”的提示词：

1. 在敏感材料被宿主读取、索引或上传前确认数据路径与授权。
2. 区分内部使用、外部服务处理、受控共享、公开披露和正式提交；授权不跨用途继承。
3. 审批绑定实际文件包、对象、用途、渠道、条件和签核；执行前校验，防止校验后替换或重新生成未批准文件。
4. 保存发送结果与回执；不明、失败、已发送分开，防重复发送。
5. 版本、语义、规则、接收范围或申请事实变化触发相关重审；保留历史审计而非覆盖旧记录。
6. 误发与提前公开启动事件流程，止损和通知必须在实际权限内进行；不得补造同意记录。
7. 指导模式、受控执行、离线及其出口覆盖按事实声明；人工操作或其他进程未受控时说明限制。

完整门禁是P1真实受控外发的前提。复杂SEP、许可和救济可后续深化，但不能据此推迟基本权限、版本、回执和事件入口。测试以合成／获准数据和无副作用替身为默认，真实外部验证需要另行授权。

## 8. 验证分层与命令管理

### 8.1 按改动类型选择证明方式

| 改动 | 最低验证 | 结果不能扩大解释为 |
| --- | --- | --- |
| 规划与文档 | 文件非空、本地链接、表格／围栏、编号／引用、状态和优先级一致；变更到能力覆盖时检查83项及相关AC映射 | 业务用例通过、现行法律核验或外发门禁有效 |
| 技能说明与资源 | 目标宿主能发现／读取、资源路径有效，相关AC输入产生可复核输出；仅静态检查则标清 | 全宿主兼容、完整专业支持或人工签核 |
| 确定性工具 | 目标单测／契约测试、异常与边界、版本变化；必要静态与类型检查 | 外部服务或法律结论已经验证 |
| 数据契约／状态 | 合法输入、缺失／冲突／未知、序列化、消费者兼容与审核失效 | 字段齐全即事实真实或审批有权 |
| 导出／渲染 | 代表产物实际渲染，检查分页、裁切、图文、附注和隐藏信息 | 所有格式／设备合规或官方已接受 |
| 外部适配与外发 | 安全替身测试、适用DG、明确环境与出口覆盖；获准后才做外部验证 | 替身通过即生产已受控 |
| 专业规则／判断 | 当前适用来源、获准案例、预先确认的专业预期与独立审阅 | 模型评分或格式检查能替代专业结论 |
| 打包／发布 | 文件与许可证清单、独立安装、资源／依赖解析及真实支持状态 | 未验证地区或组织全流程可用 |

AC为逐能力最低用例，DG为跨业务集成用例，均不是天然存在的可运行测试。只执行本次改动及受影响边界所需检查；不要求文档小改运行全部业务评测，不用未运行的用例填通过。

### 8.2 当前可用检查与后续命令登记

已验证环境为Windows／PowerShell 5.x、Python 3.11.15。仓库根现有命令：

```powershell
python -m unittest discover -s evals
python -m compileall -q tools evals skills
```

2026-11-01 LIFE-04续建后主代理实际全量为409测试、13.699s、OK、无skip，编译退出0；此前386及399测试为历史基线。本轮结果不等于完整专业AC、浏览器验证或专业签核。文档任务检查链接、阶段措辞和编号；共享SKILL示例/包内说明受影响时只跑 `python -m unittest evals.test_bundle evals.test_cli` 等最小相关检查，不为纯文档无限重跑全量。不可杜撰其他构建/服务命令。

详细执行历史见仓库内唯一台账docs/implementation-progress.md（不在本地包白名单）。

可用的只读Git检查：

```powershell
git status --short --untracked-files=all
git diff --check
git diff --cached --check
```

### 8.3 失败处理
