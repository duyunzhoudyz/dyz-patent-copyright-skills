日期：2026-10-31。状态：目标规格与当前辅助边界同步，83项顶层编号保持不变。获授权实现已有共享层、四业务模块、安全预览与含许可本地包；83项catalog均为synthetic_helper_only，已有合成AC/DG分支测试。本文件保持完整任务、输入、输出、阻断与验收目标，本次不修改工具或测试。适用规则、身份与专业结论仍待逐组合核验，表内AC/DG标识不是完整通过证明。最近一次既有实现的主代理全量结果为386测试通过无skip及编译退出0，详情以仓库内唯一台账docs/implementation-progress.md为准；台账不在本地包白名单中。

- [能力蓝图](capability-blueprint.md)维护产品范围、11个能力域、83个顶层ID、职责和适配轴。
- 本文件维护各ID的最小任务契约、下级专业分支和审查发现的覆盖关系；不把一行规格等同于完整专业规则。
- [跨业务披露设计](disclosure-and-handoff.md)维护交接、权限、外发审批、执行与事件契约，DG用例以该文为准。

- README只摘要上述设计、可运行入口和支持边界；七仓库分析保留固定研究时点，不作为标准业务已验证的证据。

判断“规划覆盖”看任务能否找到责任人、证据、输出、异常和验收；判断“业务支持”必须另有规则核验、实际实现和评测记录。不能用能力数量、目录数量或笼统完成百分比替代。

## 2. 每项能力继承的公共规格

下表是所有83项规格的共同部分；第3节逐行补齐差异字段，二者合起来才是一张规格卡。实现前只将当前工作包细化为工具参数和真实规则，不一次预建83个目录或大型平台。

| 字段 | 共同要求 |
| --- | --- |
| 标识与责任 | 顶层ID稳定；业务责任按第3节分组继承。共享工具不能变成专业决定者；每次任务指定实际责任人及授权依据 |
| 触发与目标 | 明确用户要完成的单项任务或阶段，不以识别到关键词就自动启动全流程、联网、提交或公开 |
| 适配条件 | 专利／软件版权记录法域、权利类型、技术领域与程序阶段；标准另记录组织、标准类型、编制阶段及法律／合同适用背景 |
| 前置事实 | CORE-01路由、CORE-02权利／贡献事实、CORE-03材料、CORE-05适用规则、CORE-06版本按任务需要提供；某项不适用须说明理由，不强求不必要个人信息 |
| 输入及依赖 | 输入有ID、位置、版本、哈希、来源、权限与关键时间。依赖是本次所需的版本化材料，不要求上游整项能力或所有地区全部实现 |
| 专业步骤 | 识别适用规则与例外，建立逐事实／特征／条款映射，区分已证实、推断和待判断，形成输出及问题清单；不以统一风险分代替专业推理 |
| 输出与状态 | 工作稿、证据、差异、未解决项、规则及工具版本、检查范围、跳过项、责任人分开记录；状态区分草稿、待补证、待专业审阅、通过、不通过、不适用、失效 |
| 阻断与恢复 | 缺事实、规则、权限或必要验证时不得标通过；可返回清楚标记的部分草稿。说明需要补什么、由谁处理、补齐后重跑哪些检查，不静默降级 |
| 变更传播 | 用输入版本和引用关系定位受影响产物／审核。内容、规则或适用条件变化需重新判断；历史记录保留，旧签核不能自动继承 |
| 外部动作 | 读取敏感材料前检查宿主数据路径；联网、模型、外部审阅、缴费、提交和公开分别授权。凡涉及披露复用外发契约，不在各skill重复造门禁 |
| 验收证据 | 第3节AC是最低任务用例；每例落地时补正常、失败／未知、不适用及版本变化输入，预先固定预期结果、允许来源和专业判定；保存实际输出和审阅，不靠自评分 |
| 支持声明 | 设计、规则研究、实现、专业评测、候选包验证分别记录。已检查文本不等于实际试验、正式提交、登记、授权、标准批准或认证 |

同一名称“通过”只属于具体检查、版本和适用组合。专业审阅通过、披露许可有效、实际发送和官方／组织程序完成是独立状态。

## 3. 83项最小能力规格

“主阶段”指最早完整主任务的目标阶段，不是本轮已经执行；某任务的基础契约可在P0先定义。专业前提无法满足时，仅保留已注明限制的辅助功能。各AC由该组业务负责人制定专业预期，LIFE-04维护回归追踪，共享层只执行检查。

## 4. 专业深度补充：下级任务而非增加顶层目录

### 4.1 专利日期、披露义务与程序异常

- **日期与现有技术（PROC-01/02、ANALYSIS-02、SEARCH-03/05）**：区分申请、优先权、公开、归档、取得、送达日期；按技术内容及组合核实有效日期。先申请后公开文献、自公开及例外、不同权利人的披露等按具体制度分别判断，不引入一个全球布尔值“在先”。
- **信息披露与引证义务（PROC-04/05/06、LIFE-01）**：美国IDS只是目标适配之一，不把它推广成各地同名要求。来自检索、标准研究、其他地区OA的新材料触发适用性检查；输出需处理事项、责任人、期限依据、提交版本与回执。没有规则或事实时列待判断，不能自动发送，也不能仅做文献收藏。
- **后续与并行申请（PROC-07）**：记录母案／分案／延续／新增内容及适用的多案衔接，逐内容保留原始支持和日期；新增申请不是对既有公开的通用补救。
- **异常与救济（PROC-04/06/08/09、LIFE-01）**：覆盖提交失败、漏件、错填、期限失误、恢复／其他救济适用性、授权文本差异。基础异常识别与不明状态在P1具备，复杂正式救济P2深化；不把救济结果写成既成事实。

### 4.2 软件主张范围、权利处理与争议

- **登记对象决策（SW-01）**：客户端／服务端／微服务／插件、旧版／升级／改编、多个主体与第三方组件，先形成软件—版本—主体—主张—排除表，再选择源码和文档。软件完成、发表／分发等事实与某次Git提交或上线事件不直接等同，按目标制度核验。
- **材料处理决定（SW-03/07）**：每类内容输出可主张、需排除、需保留说明、需补许可或禁止处理，不只列许可证名字。人类贡献据事实记录，无法支持时保留未知；不改写成“AI只排版”。
- **SW-08拆成两个任务组但保留顶层ID**：一组负责地区保护／登记适配；另一组负责权属与侵权证据准备，包括版本保全、接触和来源、相似表达定位、功能与表达区分、既有／第三方内容排除。合法取证范围和正式法律意见单独审阅。

### 4.3 标准效力、治理、试验与修订

- **三种效力分层（STD-02/04/07）**：条款要求强度、标准性质、被法律／监管／合同／采购纳入后的义务分别记录；“应”不是法律强制性的充分证据。
- **组织治理（STD-03/09/11）**：参与资格、代表权限、利益相关方覆盖、利益冲突、意见与决定映射、表决条件、重大修改、重新征求意见和异议／申诉均有记录位置。具体阈值、期限和程序由组织适配提供，本轮不编造统一规则。
- **方法学（STD-06）**：按标准类型选择样品与覆盖、环境和设备、校准溯源、测量不确定度、重复性／再现性、实验室间比较、互操作／负向／异常测试、临界值判定。记录不适用理由，不能为术语或管理条款强造实验。必要方法学条件是当前案例的前置要求，不能以专业工具计划P3为由跳过P1验证。
- **修订影响（STD-07/12）**：按组织规则区分勘误、修改、修订、替代、废止，记录并存与过渡、下游引用／产品／既有符合性结论及新披露影响。只生成新版文件不算完成修订闭环。
- **知识产权与竞争问题（STD-08、RIGHTS-06/07）**：分别处理政策声明、签署权限、许可承诺、必要性、FTO和竞争合规疑点。发现不必要排他实现、许可讨论越权等时转有资质专业审阅；不扩大为自动提供完整诉讼或反垄断服务。
- **领域公共要求**：安全、隐私、无障碍、环境等仅在范围、规则或风险适用时形成要求与验证；不把这些统一填入所有标准，也不因没有专门顶层skill而漏掉适用义务。

## 6. 评测落地与停止条件

1. 每个即将实现的能力选择明确适配组合，核验现行规则、取得材料权利、补齐角色及AC实际样例，再开始该能力实现；规则未知时只允许做不依赖该规则的辅助任务。
2. AC覆盖各能力最低行为，DG覆盖集成安全；不是完整测试集。实现时为每个实际分支补正常／异常／未知／不适用／变更样例，专业人预先确认预期，保留相反证据和失败结果。
3. 任一未授权外发、虚构事实、错误继承审批或误报正式状态，阻止相关组合放行。召回率、漏检率、格式等其他指标的阈值按任务风险和标注样本确定，不设无依据的全球分数。
4. 本次文档同步检查83项ID、17项发现和AC/DG引用保持不变，外发流程与P0/P1依赖一致、文档链接可达；不得把文档一致性检查写成业务门禁或专业能力测试通过。
5. 仍需后续工作：逐组合规则与材料许可核验、专业审阅和真实基准、尚未实现的完整法域/专业工具、真实出口与业务运行验证及发布授权。已有本地辅助和合成测试不能替代这些证据。
