# CN 专利争议、绕开与有限许可的完整工作方法

适用RIGHTS-01—06及SEARCH-07，衔接WP-08/10。面向中国大陆发明/实用新型的内部工作意见；本轮实作仅发明装置权项、网关存储/确认机制，不代表全部专利类型、法域或诉讼能力。返回[技能入口](../SKILL.md)。先读[当批规则研究](../../../references/jurisdictions/cn-disputes-evidence-20261101.md)，完整示范见[澄湾网关](complex-cn-example.md)。真实行动前核当前规则和时间效力，不把旧法条号、草案或合成档案当成现行适用证据。

## 1. 先建可分析的案卷

读取获准的完整权项、说明书/附图、审查与无效历史、权利状态、产品版本和实施行为、合同/附件/签署资料。权项不足就定位缺失；产品只给广告时列取证需求，但对已给具体机制应实际分析，不能整份意见都退回“待核”。

| 固定对象 | 最低记录 | 具体错误防止 |
| --- | --- | --- |
| 权利 | 地区、种类、申请/优先权/授权日、主张权项及全部引用限定、有效版本和状态时点 | 专利编号不代正文；从属项不能漏被引用内容 |
| 实施 | 产品硬件/固件、主体、制造/使用/许诺销售/销售/进口、地域与过去/拟未来时点 | 装置权项的配置动作不是自动改成方法权项；销售风险须接真实行为 |
| 证据 | 原件/副本/摘要/口述、位置、版本、取得方式、对象、支持及反证 | 未见不同于缺少；哈希仅绑定字节，不证明官方真伪 |
| 许可 | 权利链/负担、有权主体、合同/附件/变更、效力条件、范围与付款 | 谈判意向不等于许可；一主体许可不默认包含独立代工人 |

旧文件保留为旧时点证据，新材料建立依赖变化。失效是某意见不能再直接采用，不是删除历史。未授权采集秘密或入侵设备时只列合法取证路线。

## 2. 从解释到逐要素意见

把结构、动作、位置、先后顺序、条件与组合拆为可定位限定；前序、从属引用均不能跳过。每一行给“原文—候选解释—内部证据—产品机制和反证—相同/非相同/未观察/未知—下一判断”。采用最小必要解释，不把实施例所有细节加入权项，也不抹掉明确位置/顺序。

技术事实改写后，逐项回看来源中的动作、作用对象、条件、地点与先后关系；保留来源位置，把事实原句与解释分开。例如“CRC验证后写入数据”不能改成“写CRC后写入数据”：验证、计算和存储是不同动作。术语或图示不足以确认实际动作时，标明歧义及其影响，不用顺口的复述补出来源没有的机制。

说明书特殊定义、相关权项、附图、审查档案按具体争点使用。见“被配置为”不机械认定或排除功能性特征：先核是否可以从权项直接明确实施方式；若适用功能性规则，则落实到说明书不可缺少的实现特征及相应等同，不用广义结果替代。装置的动作配置需证据证明设备具备相应实现，不能仅拿一次演示推断全部配置。

文字比对结束后单独处理有意义的等同争点。每个变化特征比较手段、功能、效果，以及被诉行为发生时普通技术人员能否无需创造性劳动联想到；技术证据不足就明确缺口。再审查授权/确权限缩、放弃、说明书披露但未主张方案等边界。所谓限缩被明确否定须有完整档案依据，不能用销售员口述或单页推翻。

给条件性结论的粒度为“某权项×某产品版本×某行为×某地/时点”。说明支持何种落入风险、哪项明确非相同、哪项等同尚未排除；不将“未找到一个特征”直接变成全产品无风险。不用百分数/红黄绿替代推理。

## 3. 四条工作路线各自交付

| 路线 | 必须形成的正文 | 与其他路线的边界 |
| --- | --- | --- |
| 侵权 | 解释、逐要素、文字/等同、反证、行为和许可影响、条件意见 | 已获许可的特定行为可能允许，但范围比对仍有价值；许可不替代技术事实 |
| FTO | 产品/行为/地区/时间边界、概念/主体/分类和同族计划、当前状态核验、优先风险与覆盖缺口 | 单权项不落入、自己授权、标准采用或一家许可均不是全局通行证；未执行检索只能交计划 |
| 无效 | 关键日依据、每份文献实际披露/公众可得性、单篇/组合理由、反证、证据与程序准备 | 取得日不是公开日；组合要有理由，不以两篇拼图直接否定新颖性；请求不等于已无效 |
| 绕开 | 改何限定/关系、两个真实候选的取舍、代价、技术验证与重新比对/检索 | 草案不等于已制造验证；不能为了规避牺牲既有强制业务需求再报交付成功 |

无效与现有技术抗辩的对象不同：前者评权项授权条件，后者按适用规则核被诉技术与现有技术的对应。时间效力要按申请、被诉行为和程序分别审阅；不要统一套评估当天法律。材料足以否定某个线索的充分性时，应写明为什么不足，而不只列“待核”。

## 4. 冲突证据必须解决具体争点

较新不自动更可信；来源是官方也不代表对象和事件匹配。对登记状态先核标识、事件、时点、完整性及后续记录；对技术视频先核设备/固件、事件含义、是否可见关键内部动作。不同事件可先后并存，例如本地提交后ACK、远端归档更晚并不冲突。

可由现有材料解释的冲突写出解释和支持强弱；仍不可解决的事项列责任人、具体原件/测试和影响结论。旧状态不直接宣布权利消灭；即便有无效/终止，也要单独核期间及合同/历史费用后果，不能把一个状态词变成自动全额退款或对外承诺。

## 5. 绕开必须通过技术可行性筛选

每个候选列目标限定、变化后的完整机制、仍有的限定、等同及其他权利风险、功能/可靠性/成本/部署影响。验证计划写输入、状态与故障注入点、观察证据及已有需求判据；需求未给数值时不自造阈值。串行样机通过不能证明所有故障、并发和商业部署。

保留、待定和淘汰的路线都须各交一份自身的验证方案。被淘汰路线以失败复现及可能推翻淘汰理由的反证为验证目标；不能只写排除理由，也不能把另一架构的测试表当成该路线已具备验证方案。逐路线绑定以下字段：

| 验证字段 | 必须落实的内容 |
| --- | --- |
| 对象与输入配置 | 路线标识、设计/样机与软硬件版本、存储/确认等相关配置、输入数据及初始状态；尚无样机的说明拟配置，不能冒称实物 |
| 故障点与步骤 | 按该路线自己的事件顺序定位故障窗口，写清准备、触发、观察、恢复和复查步骤；无法控制或观察的窗口列为限制 |
| 观察证据 | 哪些原始事件日志、时序关联、输入标识、存储状态或恢复读回能证实失败；同时列什么实际观察可能反驳当前机制推断，不能只采支持材料 |
| 判据与结论影响 | 引用已有需求的原义，分别写何种观察构成违反、何种观察要求重查淘汰依据；未知阈值交需求负责人确定，不降低原需求；一次未复现也不等于可靠性或绕开成功 |
| 执行与状态 | 执行者、设备/数据/故障注入授权、测试尚未实跑或已给记录的实际范围；拟议步骤与已取得结果分开，授权不足仅限制测试执行，不阻断内部方案编写 |

交付前按路线逐一核这些字段，特别检查淘汰路线是否只留下“不可用”结论。未实跑时仍交可复核的失败复现/反证方案，保留当前淘汰状态；只有新证据或获准的新需求使依据变化，才启动对应版本的重新分析。

若方案先确认后异步保存而业务要求已确认记录断电恢复，当前事实已暴露矛盾，应排除为本轮可交付候选。只能另行提需要需求负责人决定的改变，不能默改“接受确认”含义。远端持久化候选要测断网、服务端失败、重试、确认丢失/重复和版本混用；还需成本与部署确认。

## 6. 许可差集转成完整有限条款

先逐格核既有明示许可与计划差集，至少含权利、主体、产品版本、地域、期限、制造/使用/许诺销售/销售、代工与客户/分销/再许可。既有范围明确成立的部分照实交付，未知不冲掉已知；未覆盖则写具体缺口。合法售出后的法定权利用尽等问题按实际来源处理，不以条款宣称消灭法定效果。

起草不是仅写“增加销售许可”。有限替换稿须自成一段可谈判文本：当事人/标的和版本、授权性质与范围、命名代工人的允许用途/转委托边界、地域与排除、期间及权利存续、费用方案、已有保密和其他条款关系、变更/签署/生效条件、历史行为是否处理。没有商业指示的价格不能填猜数；已有指示标明是一方诉求、尚待同意。

不把一般保证或赔偿条款写成FTO无风险；不因新方案可能不落入而推定许可已获。拟许可范围可作为争议预防谈判选择，未覆盖的海外专利、其他主体、其他权利均保留。竞争、出口、交易效力等复杂问题超出本次依据时明确专业交接，不暗加全面竞业限制。

## 7. 三件交付及变更重审

用户正文交完整可读工作意见和替换条款；内部审计交证据分级、反证、商业底线、规则/假设与未执行事项；行动单交实际负责者、材料、授权和恢复条件。用户正文可用于内部讨论不等于获准向对手、客户或公开发送。

产品、权项、状态、地域、供应链或合同变化分别使矩阵/等同/FTO/技术验证/许可/签署与外发包待重审，不凭旧报告盖章续期。内部整理和起草按已有授权继续；发函、无效/诉讼、签约、付款、公开报价/销售、秘密外发须单独绑定实际包、接收者、用途、渠道、有权人和条件。共享工具不能替专业判断或执行权限。

行动单按每个实际动作单独成行，至少逐行填写“动作、文件包及版本、正文/附件边界、对象、用途、渠道、批准角色、当前状态、恢复条件”。同一动作有不同对象或渠道时继续拆行；发函与起诉、签约与付款不能共用一个含混条目。已有文件或候选条款须写其实际标识、版本和纳入/排除范围；尚未组包则列本次可识别的候选材料并注明未封包，不能把已知项也留成“以后另定”。

| 动作种类 | 逐行动作绑定时要解决的具体问题 |
| --- | --- |
| 已授权内部整理/讨论 | 明确本次正文与内部审计各自版本、已知内部接收角色、讨论用途和已获准的本地渠道；在既有范围内继续，新增对象或出口另核 |
| 对手发函/谈判 | 区分工作意见、谈判条款与拟发送函件；逐件确定哪些正文/附件可发、收件主体、谈判用途及发送渠道；商业底线和内部反证审计不自动随附 |
| 无效请求 | 定位拟用权项版本、请求稿及证据目录、各证据完整性与来源权限；实际申请主体、受理机构/提交渠道按已有事实填写，未核部分明确缺项及核定角色 |
| 诉讼动作 | 单列诉状/答辩或保全申请等具体动作及拟用证据范围；当事人、程序目的、管辖和递交渠道分别核定，不借无效请求的一行代替 |
| 签约 | 绑定可识别的协议候选及附件版本、当事人和签署用途；写签署方式、双方批准/签署权限与生效条件状态，不把谈判稿当已获签署授权 |
| 付款 | 绑定合同/账款依据、付款事项与已知金额条件；收付款主体、账户、付款渠道和财务批准角色独立核对，缺少账户不得猜填 |
| 公开报价/销售 | 绑定拟公开报价或销售材料、产品版本、供应链和地域/期间；分别核对象、公开/交易渠道及商业批准角色，内部起草许可不等于这些行为获准 |
| 技术秘密或证据外发 | 定位具体文件、摘录/脱敏版本和允许正文边界；明确接收主体、用途、出口渠道、可再转发范围以及保密/披露批准角色，不能借一般“可讨论”扩大 |

上述是组织行动单的程序，不是预填本案对象或授权。每行每个字段都使用资料中已知内容；确实未知时，写“待核：具体缺项；由何角色核定；未满足时该动作保持何状态”。缺少具体负责人时可标职责角色待指定，但不能虚造姓名、法院、地址、账号或渠道已开通。恢复条件应列该行尚缺的文件定版、对象/渠道核验、必要专业复核与有权人批准；满足后仍做发送/执行前的包版本复核。不能仅在总则写“高影响动作暂停、以后另定”来代替逐行绑定，也不能因此暂停已有授权的内部整理。

交付前从完整正文反查原案卷、每个必要限定、反证及变更依赖；不要将示范、静态链接、机器回归或作者审阅升级为独立专业验收。
