# 编制说明：内部11节示例与profile适配

阶段 5 的必备文件。编制说明解释正文，**不能悄悄增加正文义务，也不能宣称未发生的会议或表决**。 返回[阶段门禁](stage-gates.md)。

## 一、性质

编制说明是送审材料的解释性文件，不是正文的一部分。它与正文的关系：

- 正文写"是什么要求"，编制说明写"为什么是这个要求"。
- 编制说明中出现新的义务性表述，视为正文漏写，须回到条款层处理，不得只在说明里补。
- 说明可以记录分歧与未决，但不能用"待进一步研究"掩盖没有责任人的缺口。

## 二、内部11节结构

以下是内部整理profile，不是通用法定11节要求。实际组织、标准类型和阶段使用已核来源的profile；v2绑定profile标识/hash及其必需章节。不得仅换标题就宣称符合组织模板。

每节字段：`id` / `heading` / `body` / `source` / `state` / `owner`。`state` 取 `explicit` / `inferred` / `unknown` / `not_applicable`：

- `unknown` 必须带 `question` 与 `owner`。
- `not_applicable` 必须带 `reason`。
- `source` 不得留空；无来源时 `state` 不得为 `explicit`。

| 节 | 标题 | 必写内容 | 常见编造风险 |
| --- | --- | --- | --- |
| 1 | 工作简况 | 任务来源、起草单位、协作单位、主要起草人、起止时间 | 编造参与单位或起草人 |
| 2 | 制定背景与目的 | 产业现状、具体问题、拟解决的缺陷 | 空泛行业趋势代替具体缺陷 |
| 3 | 编制原则与依据 | 遵循的导则、引用的上位标准、政策依据 | 引用未核版本或不存在的文件 |
| 4 | **主要技术内容确定依据** | 每项关键技术指标/条款的依据与来源 | 无实测依据却写"经验证" |
| 5 | 与国内外同类标准的水平对比 | 对比对象、版本、对比项、结论 | 只写"达到国际先进"而无对比表 |
| 6 | 与有关法律法规/标准的关系 | 引用关系、冲突处理、纳入方式 | 把标准与法律效力等同 |
| 7 | 重大分歧意见的处理 | 分歧点、各方理由、处置结论、是否重征 | 以多数票代替技术论证 |
| 8 | 标准性质与实施建议 | 强制/推荐、实施日期、过渡期建议 | 擅自确定生效日期 |
| 9 | **征求意见处理情况** | 意见总数、采纳/部分/不采纳/待决统计、与汇总处理表的对应 | 有汇总表却无本节，或统计数与表不符 |
| 10 | **验证情况** | 试验/检验/互操作的实际范围与结果，或"未执行" | 把计划写成已执行 |
| 11 | **未决事项与后续工作** | 每项 question / owner / 阻塞哪一步 / 恢复条件 | 用"待进一步研究"掩盖无 owner |

第 4、9、10、11 节是高频编造区，逐节要求见下。

## 三、四节高风险项的写法

### 第 4 节：主要技术内容确定依据

对每项关键技术指标或核心条款，写清：

- 指标是什么（对应条款 ID）。
- 依据来源（试验数据、国内外标准、行业实践、理论推导）。
- 来源的适用条件（样本、环境、版本）。
- 若依据是"沿用既有标准"，写清是哪一版、哪一条。

**不得写：** "经大量试验验证"而无样本与环境；"参考国内外先进经验"而无具体对象。

### 第 9 节：征求意见处理情况

这一节是[汇总处理表](comment-disposition.md)的镜像，数字必须与表尾统计一致：

```
共收到意见 N 条，其中采纳 a 条、部分采纳 b 条、不采纳 c 条、待决 d 条。
涉及条款 M 条，其中实质技术变化 k 条，重大修改 j 条。
少数意见 x 条，保留原文及来源（见汇总处理表附录）。
```

并写明：未决 d 条的去向（第 11 节对应条目）、重大修改是否触发重征意见（依据组织规则，规则未取得则写"待组织判断"）。

### 第 10 节：验证情况

**五层分列**，不得合并成一句"已验证"：

| 层 | 写什么 |
| --- | --- |
| 验证计划 | 方法、样本、环境、判定依据；无计划写"未制定" |
| 实际执行 | 谁在何时按何方法执行；未执行写"未执行" |
| 结果 | 实际数据与观察；无数据写"无数据" |
| 专业符合性判断 | 结果是否满足要求的专业判断，须由有权人员作出 |
| 认证/认可 | 是否取得外部认证；未取得写"未取得" |

只完成计划时写"已制定验证计划，尚未执行"，不能写"验证通过"。

### 第 11 节：未决事项

每项至少四条：

```
question: 具体待确认的问题（不是"进一步研究"）
owner: 责任人/责任单位
blocks: 阻塞哪一步（送审/报批/发布）
recovery: 什么条件下可以恢复推进
```

没有 owner 的未决项不算记录，视为该节未完成。

## 四、与正文的版本绑定

编制说明须绑定其解释的正文版本：记录当前 `clauses` 的 digest。条款改动后：

- digest 不匹配即为旧版说明，须重写受影响小节。
- 不得只改数字不改陈述，也不得保留旧结论而仅追加新段。

结构、digest及字段可机检；自然语言内容是否充分解释条款、资料是否真实及适用组织规则仍须专业核对。哈希相同不证明专业正确。

说明中的第9节统计、第10节验证摘要及第11节未决直接消费当前原意见／处置／验证，不另存可绕过真源的第二套决定。`comment_content_binding(payload, outcome)`重算意见、完整决定与系统推导基线范围；只有真实角色核对并显式调用`confirm_comment(payload, comment_id, confirmation)`才形成新确认记录。缺绑定的旧confirmed为unbound，内容／范围变化为stale，历史保留；本节不能因正文拟文一致或确认hash齐全就写成决定已落实、验证已完成。

技术依据可通过`source_bindings`把说明段落、命题及适用版次连接`source_reports`的具体citation。成件时须实际加载获准报告、原件及提取记录，核原字节hash和逐字页段；业务payload自报passed不能替代。局部引文不证明全文无冲突，来源partial、命题待审及未重新看原页分别保留；原件、报告、引文或命题变化后只承接可证明无依赖小节，其余重核。最终块／显示位置来自同一源映射，未生成PDF时不填物理页码。

## 五、结构校验与版本选择

显式`contract_version: 2`进入新闭环；缺省/1保留legacy，未知显式版本（包括布尔值）拒绝。v1 schema的路径及标识保留。v2要求实质正文、profile和条款版本绑定，并从原意见及处置派生统计/未决；声明摘要与派生结果矛盾时保留问题，不能改hash冒充重写。缺说明可生成明确缺件的内部草稿，不进入可交专业审阅状态。以下为legacy兼容行为，不是v2的完整性定义。

AF-03（2026-11-13）：`_candidate` 收到 `compilation_note` 时逐节核对——11 节齐备、`state` 受控、`owner` 非空、`state=explicit` 须有 `source`、`unknown` 须有 `question`、`not_applicable` 须有 `reason`、第 11 节 `open_items` 四字段齐备；`clause_digest` 不匹配报 `compilation_note_stale`。声明 `require_complete: true` 而缺节时直接拒绝。

**已交 `explanatory_note` 角色文件却没有结构时直接拒绝**（`compilation_note_structure_missing`），空对象同样拒绝——杜绝"有文件名、无内容"的空壳。只有既未交该角色文件、也未传结构时保持历史行为不额外报错；该情形由送审清单的缺件项负责。

## 六、交付形态

- 正文用 Word 出件时，编制说明与正文分别成文件，不合并为一个文档。delivery生成版本为1.7，有限检查标为`assessment_version="standards-consistency/1"`；机器发现、待语义复核、未覆盖和未执行分别展示。实际原条款书签的有限核对保存在`internal/checks.json`的`finite_review`；纯业务调用只核输入文字、实际文件未核。manifest的`pending_reviews`不能被issues为0抹掉，纯待审仍为`internal_draft_needs_review`，不迁作专业通过。
- 原创渲染profile为`dyz-standard-internal-v2`，与业务章节profile和规则profile分开绑定。标题、章条、附录及目录来自同一显示映射；PAGE的物理页码、导航域结构、实际刷新与页面观察分别核，不从字体或模板存在推定组织符合。
- `internal/source-map.json`中的`clause_locations`连接稳定ID、显示号、书签和实际文书块；`internal/projection-coverage.json`核每条核心记录的读者投影及内部叶子保留。长说明、理由和未决不得只藏在原JSON或被短概览截断，仍需完整集合与最终字节回验。
- 新verify遇1.1生成包返回`standard_generator_version_unsupported_use_frozen_tool_or_new_directory`；旧文件及当时结果保留，用对应冻结工具复验或新目录重建／重新确认，不覆盖旧包或替换旧hash。
- 编制说明中的内部风险、IP 策略与私有审计**不随正文默认发送**，走三栏分流。
- 组织有固定表式或固定章节顺序时以组织要求为准；本结构用于组织要求未取得时的内部整理，两者差异须在送审前核对。

## 七、不适用范围

- 本文件不判断技术指标本身的正确性，该项属专业审阅。
- 不替代验证记录与试验报告；第 10 节引用的是那些材料，不是复述。
- 编制说明不是立项申请书，也不是审查意见答复；三类文件的对象与阶段不同。
