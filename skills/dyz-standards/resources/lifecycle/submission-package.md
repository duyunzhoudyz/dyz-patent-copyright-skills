# 送审/报批包装配与三栏分流

先确定任务用途，再选择对应材料路线。Skill 开发、试用或本地技术分析按下述本地验证要求交付；真实制定者送审/报批适用阶段 5—6，个人或公众反馈/勘误适用征集通知或受理规则。装配应**逐件核版本、核权限、核缺件**，并把内外材料分开。返回[阶段门禁](stage-gates.md)。

## 先辨提交路线并主动补齐真实案例

先从用户目标确认下列路线；已有意图足够清楚就直接推进，无法区分时只澄清决定交付类型的问题。缺自有案例不等于缺任务授权，不应把寻找案例、模板或公开程序退回用户。

| 路线 | 可实际完成的工作 | 必须保留的边界 |
| --- | --- | --- |
| Skill 开发/试用、本地技术分析 | 用获准公开真实案例核原文、改文、正反例、文件产物及可重复步骤 | 业务署名、联系方式、提交者声明、组织批准与发送授权本次不适用；能力结论限于实际检查范围 |
| 制定者/起草组送审、归口单位报批 | 按实际组织规则整理正文、编制说明、意见处理、验证及组织材料 | 公开项目不能替代用户的起草组身份、组织记录或真实签核 |
| 个人或公众征求意见反馈、已发布文本勘误 | 主动选取合法公开真实文本，完成官方反馈表或规定格式、具体意见与依据 | 属于参与者意见，不冒称原起草组已完成五件送审材料或已采纳意见 |
| 全新标准立项申请 | 研究必要性、现有覆盖、范围与申报材料 | 取得真实承担单位与适用申报程序；公开案例只作评价素材，不能替造申报主体或立项批准 |

### 本地开发验证的交付要求

按目标选择可合法处理的固定版本；历史或已截止项目可用于验证，记录其时点即可。先完成原文定位、具体意见/改文、可执行的正反例及实际文件检查，再报告输入版本、运行方法、预期与实际结果、失败和限制。真实技术验证与构造输入分开标识；XML/XSD的具体检查见下文。

案例及生成材料只在获准本地目录保存。为便于读者复现，可把原创输入、必要代码与通用操作方法纳入 Skill；第三方全文、官方表及本地生成材料分别核分发权，不因验证成功自动进入公开包。业务身份字段保持未填写；交付清单的行动栏写“本地验证，本次无提交任务”，不将身份、签章、专利提交声明或发送授权列为开发阻塞。人类专业审阅、产品认证和真实组织受理未发生时如实说明，不能以索取这些业务事实代替对 Skill 可用性的检查。

### 从公开材料做到可审阅成件

1. **主动选择可用项目。** 用户没有案例时，按目标领域检索主管部门、标准组织、归口机构的官方公开项目；优先选择正在征求意见、全文及反馈方式可合法取得、与目标相关的真实案例。勘误核正式版及受理渠道；历史或已截止项目仍可分析，但不包装为仍可征集的提交机会。
2. **补齐规则与原件。** 取得并登记官方通知、标准编号/计划号、性质、阶段、稿件版本、公开日、截止日与时间规则、提交渠道、参与资格、格式和必要附件；分别获取征求意见稿、编制说明、官方表及适用规则。保留来源URL、取得日期、原文件名与文件哈希，核通知和附件是否同一版本。必要全文或格式无法取得时继续查合法公开来源或换用符合目标的真实项目；仅将仍无法解决的具体缺件列入内部清单，不拿摘要充作全文。
3. **逐项建立证据。** 阅读意见所依赖的正文、交叉引用和编制说明，给每项意见稳定ID，绑定标准/文件版本、条号、原文及必要上下文、原件页码与PDF页序或其他可复核定位。无稳定页码的材料使用标题/段落/表格行等实际定位，不编页码。核术语、引用、否定词、条件和例外，防止只截一句形成错误判断。
4. **完成可执行改文。** 每项写清问题、原文、拟替换/新增/删除文字、理由及证据；可选方案与现有要求分开。文件审查即可支持的歧义、引用或一致性意见，应完成实质分析，不借缺行业实验停工；涉及性能阈值或试验结论则需真实依据，缺时只给验证建议。区分公开真实记录、作者分析、构造示例和未执行计划，不替造身份、组织决议、行业数据或实验记录。
5. **按官方格式成件并回验。** 用官方反馈表新副本或规定格式填写实际意见，按允许方式附逐项论证和必要附录；复用现有Word新副本、成件与回验入口，不为公众反馈强行生成五类送审文书。核表内意见、拟改文、理由和证据ID一一对应，并核版本、条号、引文和实际分页。原创意见与下载原件分开保存；公开下载不等于再分发许可，对外附件仅采用获准材料或必要引文与来源链接，不默认附送整份原件。
6. **按任务用途收尾。** 本地开发验证交实测结果与可复现步骤，身份和发送条件记为本次不适用。真实业务准备先完成实质正文，再于正式外发前按官方字段取得真实姓名、署名单位（如适用）、联系方式、提交者资格及具体包/对象/用途/渠道的授权；缺什么就逐字段记录，不虚构占位身份，也不在正文塞满笼统免责声明。允许个人参加的项目无需无关组织批准。同源AI复核仅是辅助自查；专业签核须有真实人员、范围、版本和日期，材料准备完成与正式提交/受理分别报告。

检索起点示例（2026-11-14时点）：强制性国家标准《汽车数据安全要求》，计划号20261957-Q-339，公开日2026-10-20、反馈截止日2026-12-19；可从[官方征求意见入口](https://zxd.catarc.org.cn/zxd/portal/zqyj/906)与[装备工业发展中心通知](https://www.miit-eidc.org.cn/art/2026/10/20/art_1730_12851.html)定位通知、全文、编制说明和反馈表。民航行业标准《民航数据治理 运行数据共享XML模型架构规范》的[官方通知](https://www.caac.gov.cn/HDJL/YJZJ/202611/t20261113_232069.html)提供草案、说明及反馈表，截止2026-12-06；官方表明确个人反馈时单位填“/”。每次使用先复核官方期限、附件和受理要求；这些例子是公众参与路线的检索入口，不代表本技能或使用者具有起草组身份。

XML/XSD案例须分别验证XML可解析、XSD可编译及实例符合模型；可按[三层本地校验示例](../tools.md#xmlxsd-三层本地校验)在已有获准引擎中执行。对印刷代码片段补入的schema/命名空间封装、排版换行处理及诊断构造值逐项说明。用一项一变的正反例隔离层级、必选/可选、空值、代码、时间词法和数值类型问题；预期拒绝的反例实际被拒绝才算结果匹配，不将其写成原草案示例通过。业务代码含义、时区、坐标基准及未确定的精度仍交编制组确认；对外可附必要短代码与最小重构，不默认再分发完整第三方模型。

### 公众反馈/勘误的最低交付

- **官方表或规定格式：** 填入实际反馈；标识目标标准、版本和提交路线，身份待补字段单列内部清单。
- **逐项意见与证据：** 意见ID、条号、原文/拟改文、具体理由、来源版本与页码/其他定位；官方表容纳不下时按允许形式附页。
- **核验记录与适用附录：** 记录核读范围、引用/交叉引用及版本检查结果；附真实已有依据或明确标识的验证计划。构造数据不得作真实执行证据，不适用的试验写明理由，不强行填造结果。
- **三栏清单：** 按下文第三节实际列出对外正文/附件、仅内部材料和行动前条件；没有提交回执时只报告材料准备状态。

## 一、角色清单

| 角色 | 文件 | 阶段 | 缺则 |
| --- | --- | --- | --- |
| `draft` | 标准送审稿正文 | 5 | 阻塞送审 |
| `explanatory_note` | [编制说明](compilation-note.md)（按适用profile） | 5 | 阻塞送审 |
| `comment_dispositions` | [征求意见汇总处理表](comment-disposition.md) | 5 | 阻塞送审 |
| `verification_evidence` | 要求—方法—判定矩阵 + 验证计划/记录 | 5 | 阻塞送审（非实验条款须带不适用理由） |
| `reference_list` | 规范性引用文件清单（注日期/不注日期标注） | 5 | 阻塞送审 |
| `organization_records` | 立项批复、会议纪要、表决记录、批准文件 | 5/6 | **不伪造**：无则标"未取得"，状态停为候选 |
| `revision_note` | 修订说明 | 6 | 阻塞报批 |
| `internal_risk_report` | 内部风险/IP/审计 | — | 不随正文发送，独立保存 |

`tools.standards._candidate` 的 `required_document_roles` 默认已含前四类；本表在其上补充阶段归属与组织记录的特殊处理。该角色表服务制定者送审/报批，不作为公众反馈的必填角色清单。

## 二、装配顺序

先装配、后反查。顺序不可颠倒：先核清单再看正文，会漏掉"文件在但内容是旧版"。

1. **固定边界。** 写下本次路线、包版本、接收对象、用途、渠道、拟发送日期、提交者及适用的批准角色；公众反馈同时核当前期限与参与要求。行动信息缺失时先完成内部候选，按官方规则列具体缺项；不向允许个人参与的项目附加无关组织审批。
2. **逐件登记。** 每个文件记录：版本标识、来源、实际字节 SHA-256、页码/条目数、生成时间、生成方式（手工/脚本/转换）。
3. **版本对齐。** 正文、编制说明、汇总处理表、附件之间的版本标识必须互相指向同一稿；制定者材料中的 `clause_digest` 须匹配正文当前 digest。公众反馈表、逐项论证和证据须共同指向实际反馈的标准版本。
4. **内容反查。** 回读实际文书的完整受支持区间：制定者验证矩阵是否覆盖新条款、意见是否落到条款、引用是否当前版本；公众反馈逐项核原文、改文、理由、条号和页码/定位。抽查只能报告抽查范围，不能宣称全部无问题。
5. **分流。** 按下面三栏分类。
6. **清单反查。** 从清单回读每件实物，确认"清单上有的，包里有；包里有的，清单上有"。

## 三、三栏分流

真实业务交付实际列出下列三栏；本地开发/试用沿用该结构时，第一栏改写为“本地产物”，第三栏写“本地验证，本次无提交任务”，另列技术未验证范围，无需列业务身份待补。

| 栏 | 内容 | 要求 |
| --- | --- | --- |
| 拟送正文/附件 | 制定者路线的送审稿、编制说明、汇总处理表、验证材料、引用清单；或公众路线的官方反馈表、具体改文/理由及适用依据附录 | 每件带版本，清单登记实际字节哈希；仅包含本路线所需且可对外使用的材料 |
| 仅内部保存 | 风险/IP清单、下载原件与源映射、私有审计、内部审阅记录、旧版历史、身份待补字段 | 明确标"不随正文发送"；原件公开可下载不自动取得附件再分发权限 |
| 行动前仍须确认 | 包版本、接收对象、用途、渠道、期限、真实署名/联系方式、具体授权，以及本路线适用的批准角色/组织记录缺件 | 逐字段写明缺什么、谁可补、恢复条件；允许个人参与时不要求无关组织批准 |

**不得**用"尚未批准""请领导审阅"一句话替代分流；也不得把内部风险文件放进对外附件再声明"仅供参考"。

## 四、组织记录的特殊处理

组织记录、试验原件、授权和专业签核均不能由生成器补造；同源AI复核不构成独立专业签核。对制定者送审/报批路线的`organization_records`：

- 缺它时，整套材料是**内部候选**，不是已送审。
- 不得自行编写、推定或格式化一份看似正式的组织记录。
- 缺件写"未取得"，并写明它阻塞哪一阶段（送审/报批）。
- 工具侧已固定 `organization_approval: not_asserted`、`submission: not_performed`。

## 五、送审前反查清单

本节仅检查制定者送审/报批材料；公众反馈按前述最低交付及官方要求核验。

- [ ] 正文、说明、处理表、附件版本互相指向同一稿
- [ ] 编制说明符合已核profile，意见摘要与派生统计一致，未决/验证范围与当前实物一致
- [ ] 汇总处理表意见数 = 处理行数，pending 项均有 owner
- [ ] 验证矩阵覆盖当前全部 requirement 条款，非实验条款有不适用理由
- [ ] 验证只覆盖旧条款或部分模式时，未移贴到新稿
- [ ] 签核匹配当前版本与权限；旧签核未沿用
- [ ] 引用清单区分注日期/不注日期，版本核验提示已处理
- [ ] 文件哈希与实际字节取得一致，不只记录文件名
- [ ] 三栏已实际列出，内部材料未混入对外附件
- [ ] 组织记录缺失项已写明，状态标为内部候选

## 六、不宣称完成的情形

对制定者送审/报批路线，以下任一存在时，只能说"内部候选已整理"，不得说"已送审"：

- 无组织记录或其实际接收回执。
- 签核不匹配当前版本。
- 编制说明与汇总处理表数字不一致。
- 验证只覆盖旧条款。
- 包版本、对象、用途、渠道、批准角色任一未定。

接收者确认"收到"与"同意送审"是两件事；没有发送记录与组织回执不写已送审/已受理。

公众路线可如实交付"反馈表及逐项依据已准备，署名待补"等具体状态；缺身份只阻塞依赖身份的正式外发，不妨碍完成实质意见。过期或未确认渠道不得称可正式提交，无发送记录不得称已反馈，有发送记录但无受理证据不得称已受理。此路线不能升级为原起草组的送审、采纳或标准批准。

## 七、工具支持现状

`tools.standards._candidate` 已能：按角色检查文件缺失、检查条款引用是否可解析、绑定 `clause_hash` 与 `content_hash`、隔离 `internal_risk_report`、标记旧审阅失效。

AF-03（编制说明 11 节）与 AF-04（处理结果四值枚举）已于 2026-11-13 实施，见[编制说明](compilation-note.md)第五、六节与[汇总处理表](comment-disposition.md)第七节。

新增五文书入口及回验见[工具说明](../tools.md#五文书闭环与本地入口)。正文、编制说明、意见处理表、验证矩阵、审查报告分别生成DOCX；外置manifest不包含自身hash，报告不反哺本批输入。`internal/`保存输入/源映射/落地证明/完整检查，整目录不是已批准外发包。五个生成角色是工程文书角色，不替代上表全部组织送审必需角色，也不是公众反馈必须凑齐的套件。

内部阶段确认及当前选择失效已接既有ledger；不等于所有组织门禁已自动化。页级来源绑定限明确读取范围，天然事实状态等未实现项仍保持原边界；真实组织、自然语言保真、域刷新、专业/外发审批必须分别核证。
