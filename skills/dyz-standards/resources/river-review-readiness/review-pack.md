# 溪桥接口专业待审包

对象是T/CAICI团体标准路线、数据交换接口、内部草拟阶段的原创合成项目。当前技术稿为协议1.1／RS-2；协议1.0作为变化基线保留。请技术、标准化和相关IP角色分别回答下列问题，并指出需要返工的具体位置。本包只完成受审准备；没有具名专业人员、组织立项、表决、批准、正式收件或发送事实。

## 1 阅读对象与证据版本

先读[原需求](../river-demo/requirements.json)、[1.1正文](../river-delivery-source/draft-v1.1.md)和[编制及意见记录](../river-delivery-source/review-v1.1.md)，再读[来源关系](../river-source-profile.md)、[1.1补充验证](../river-v11-verification/verification.md)和[本地双进程观察](../river-local-interop/verification.md)。[1.0正文](../river-delivery-source/draft-v1.0.md)、[1.0编制记录](../river-delivery-source/review-v1.0.md)与[变化影响](../river-delivery-source/change-impact.json)供核查变化使用，不是两个同时待批准的版本。

[证据索引](evidence-map.json)绑定上述源文件、输入、首次结果及现有六份Word／PDF的字节SHA-256；问题关联当前Word的具体书签与文字SHA。输出目录只是本工作区的观察位置，不是安装依赖。完整本地包携带原创源、文件输入和绑定记录；原Word／PDF可按[研究示例方法](../../../dyz-rendering/resources/research-documents.md)在不存在的新目录重建。另行重建或外部另存后须核实际字节及目标，不能继续使用旧文件的绑定。

来源研究仅继承[2026-11-03实际读取范围](../../../../references/standards/river-source-evidence-20261103.md)，本包没有重新联网核其状态。RFC全文、受限标准全文和组织模板不随包复制；GB/T全文及模型处理、引用、复制、再分发权限仍缺。

## 2 原需求与方法适用边界

| 原需求 | 当前正文位置 | 已有检查与本次需要审的边界 |
| --- | --- | --- |
| R01 | RIV-01 | 完整UTF-8原始字节1至1024、BOM及坏编码；不是字符数、分帧或传输限制的完整规范 |
| R02 | RIV-02 | 各层转义后重复名、数字词法及对象／数组顺序；接口拒绝不能一概解释为RFC语法非法 |

| R08 | RIV-07 | 全部字段合格后才处理顺序／重放；拒绝不改状态、不占批次标识；成功接收原记录，已接受批次重放即拒绝 |

| R10 | 范围／RIV-07 | 只规定同一上下文的串行内存状态。跨重启、并发、断电／磁盘故障及确认丢失不在本案当前实现和符合性声明内 |

R10的范围排除来自原需求，不是为本次验收豁免失败。新进程空状态接受旧批次只验证新作用域，不是持久去重。若未来产品需要持久化或并发，应先提供获准的新需求、状态／故障模型及判定依据，另行处理受影响条款、实现、试验和审核；本包不为它们编造规范要求。

数值上限是原合成任务给定约束，没有行业实测或性能依据。当前对象是离散字节和状态的计算检查，不能机械填入不存在的设备校准或物理不确定度；若改为实际观测产品、计时或性能符合性，则必须补对象、样品、环境、计量和判定依据，不能继承本案结果。

## 3 请专业角色逐项回答的问题

下列问题均为待回答，不表示相应角色已经参与。P0指作出相关支持或披露决定前必须解决；P1指本组合专业审阅的必要问题。优先级不授予任何外部动作权限。

### SQ01 引用性质与应用限制 P1

技术与标准化审阅者：是否认可RFC 8259保持资料性、RQ-RIVER作为本接口额外约束的来源？请核正文RivReference／Riv02是否清楚区分合法JSON、接口可接受及原因码。若要求规范性引用，请明确采用版本、具体依赖和逐条修改，不能只要求“符合RFC”。证据为来源关系第2节、R01至R09及现有拒绝输入；需要的是有定位的引用决定及影响清单。

### SQ02 勘误5318与斜线争点 P1

技术与标准化审阅者：对已保存的2017原文第7节及勘误5318页面观察，适用解释应如何处理？当前只保留来源张力，未裁定勘误无效或直接改解析器。SB-13／14的River结果均受批次字母表限制，不能裁定通用JSON的斜线语法。请提供采用依据、适用范围及是否改变引用、条款或验证预期；依据不足则继续待决。需要的来源不是再次运行同一批输入。

### SQ03 状态作用域及产品适用性 P0

技术事实负责人和验证负责人：当前接收上下文的开始／结束是否足以支撑所拟声明的内部接口用途？请核RivScope／Riv07与R10，确认不能从内存原子更新外推跨进程恰好一次。若实际用途依赖保存、并发或恢复，请先补具体需求及故障后允许状态，当前只交范围内草稿，不以增加SQLite或并发测试自行决定业务语义。

### SQ04 独立验证与预期可信度 P1

验证负责人：已有作者看过原模型后设计的输入、A／B实现及预期，能支撑哪些有限观察，还缺哪些独立性和覆盖？请对InteropMethods／InteropResults／InteropFresh给出具体复核意见。真实独立实现须说明作者／来源、版本、实际字节路径及预期依据；未暴露写作任务须另满足保管和通道条件。第三个同作者实现、重复跑已知输入或两进程数量均不能补成独立产品证据。

### SQ05 字节解析与错误优先次序 P1

技术审阅者：请核RIV-01至08及152个既有输入的覆盖缺口，尤其重复名先于覆盖、转义后比较、整数与布尔区分、先全字段后顺序／重放、拒绝不占标识及调用者状态。需要指出具体反例或认可的要求—预期对应，并说明其来源；一次结果与预期相同不能自行认证预期正确。不要修改原输入以适配实现。

### SQ06 1.1变化与过渡条件 P1

技术及标准化审阅者：RivTerms／Riv03／Riv06和ReviewTransition是否完整处理任意起点、跳号、null及版本精确值？请说明旧系统需要什么明确配置和过渡材料；当前混版拒绝，没有已验证并存部署或自动转换。重大技术变化、重征意见及所需程序由有权组织依据决定，不由作者建议或技术测试通过代替。

### SQ07 正式结构及材料权利 P1

标准化与材料权利负责人：请明确本组织／类型／阶段适用的起草依据、表式版本，以及允许当前宿主处理、引用和分发的具体文本／模板范围。GB/T 1.1目前仅目录，不能据此做全文符合性核稿。取得条件后，请针对当前Word逐项指出结构、引用、术语、编号或格式返工；没有适用依据时保持待核，不从别的组织模板推定符合性。

### SQ08 试验判定及不适用理由 P1

技术与验证负责人：是否认可本案只作离散字节／逻辑状态检查，暂无设备计量、校准或性能结论？请按具体条款说明方法适用与不适用理由；如拟扩大用途，补样本／重复再现、环境、临界值、量值来源和判定规则。不得把给定1024字节／4记录上限当性能实测，也不为填满方法表发明毫秒阈值。

### SQ09 组织程序与意见的真实性 P1

标准化／组织程序负责人：选定T/CAICI路线所需立项、参与权限、意见处理、表决、修订分类和申投诉证据分别是什么？本例O-V01至05均为原创假设意见和作者建议，没有会议或决定。公开机制中的实名、收件后1个月等仅为已有来源观察，没有真实收件不能启动本案期限。请给出适用规则与需要补交的原件，不填写虚构代表、票数、签章或受理状态。

### SQ10 公开前保护及两路IP交接 P0

专利保护、SEP／FTO与许可角色分别审阅：当前没有真实申请、权项支持映射、必要性、自由实施或专利许可事实。若未来披露具体技术，应怎样逐内容核申请支持、时点及具体包权限？专利声明／必要性与FTO／许可分别需要什么材料和有权决定？请核ReviewIP，不用RFC版权条件、申请号或标准引用替代这些判断。

### SQ11 交付隔离与行动条件 P0

材料负责人和拟接收方角色：请核第5节实际分流是否完整保留正文、编制／意见／验证材料，以及必须向审阅者披露的未知和保留意见；风险策略和内部开发审计分别管理。任何拟外发须明确实际包字节、对象、用途、渠道、有效条件及有权批准；本次这些外部条件未提供，也没有已发送事实。需要回答具体缺件和恢复条件，不能只加一句“未批准”。

### SQ12 修改后复核与历史保全 P1

专业审阅者与工程维护者：如SQ01至11导致变化，哪些正文、引用、验证输入／预期、意见建议及Word目标需要重审？请将主要／局部返工及可维持的无关部分定位到实际版本。旧1.0、RS-2和验证补充保留历史；新文件或来源不继承旧文件审核。需要具体影响决定和复查记录，不能以包哈希一致代替专业认可。
