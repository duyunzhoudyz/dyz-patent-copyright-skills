# 国内接口与数据交换标准核心深化

适用于一个已确定国内组织、标准类型和阶段的内部草拟、意见处理或修订任务，关联STD-01—09/11/12。先读[技能入口](../SKILL.md)；需正式送审、表决或国际采用时接[后续程序](follow-up.md)。[River三案](river-example.md)展示资料充分、相互冲突和版本变化时的完整交付，使用原创合成技术材料，不是任何组织真实项目或批准稿。

本次具体规则组合为中国通信企业协会T/CAICI团体标准，官方域名cace.org.cn，不能与中国通信标准化协会或其他代号混用。已读来源、条号、发布日期、访问范围和待核事项见[2026-11-01组织规则研究](../../../references/standards/cn-organization-evidence-20261101.md)。这是一份阶段性研究，不证明每个未来任务均适用同版规则，也不代替项目授权。组织管理办法可读不代表其援引的GB/T起草文件或专利细则全文均已取得。

## 1. 先分开决定所依赖的证据

本轮补核见[River来源关系与待审附录](river-source-profile.md)及[2026-11-03来源证据](../../../references/standards/river-source-evidence-20261103.md)：完整读取RFC 8259并区分通用JSON与接口自定约束；已核官方勘误状态及其中争点，补协会申投诉机制。GB/T全文与许可仍缺。新附录不回写原三案已读范围或规范性引用，公开研究不改标为synthetic输入业务CLI。

将材料登记成四层，记录版本、定位、可读范围、用途和责任人。只有题录时不把它改写为全文审查；既有标准是否覆盖技术需求，应逐范围、对象、条件和行为核对。

| 层 | 能支撑的决定 | 不能由此推出 |
| --- | --- | --- |
| 组织真实规则及状态 | 在其组织、类型、阶段内列程序条件、所需材料和有权角色 | 技术方案可行、项目已立项或当前稿通过审查 |
| 技术需求、约束与利益方材料 | 候选条款的目的、约束和技术取舍 | 提议数值已获组织采纳；企业偏好即行业共识 |
| 可读的既有技术文件、引用及记录 | 对实际取得范围作关系和变化分析 | 未取得全文等于无覆盖；仅有新版标题即可替换旧依据 |
| 执行记录及权限 | 指定版本、输入、方法、环境下观察到的结果；具体允许动作 | 单一模型自测等于互操作；内部可读等于可公开 |

每个重要选择写一条短论证：所解问题、事实依据、所选方案、最强反例、备选及代价、谁核定。资料充分时实际选一个内部候选并形成条款，不以无限待问代替起草；尚无依据的性能阈值则不填造。给定合成任务可用明确提供的合成约束，须与真实行业事实分开。

## 2. 从模糊愿望收敛成完整可检查的接口

“快速、兼容、可靠、所有平台通用”不能直接成为合格判定。先找具体生产者、消费者、消息边界、上下文和失败后果。将技术选择写成以下可观察行为；任务确不涉及的项目给出边界理由。

| 问题 | 正文应给的决定 | 常见反例 |
| --- | --- | --- |
| 数据边界 | 字节编码、完整消息边界、长度计数、允许字节/字符形式、是否容许BOM | 两端都称UTF-8，一端带BOM；按字符数限长而非字节数 |
| 结构及解析 | 顶层类型、必需/可选/禁止字段、重复键、未知键、空集、顺序和嵌套 | 先解析覆盖重复键，后作字段检查；未知键被静默丢弃 |
| 数值与文字 | 类型、单位、闭/开区间、精度、布尔与整数区别、空值及非法值 | 布尔被当作整数；浮点1.0和整数1无意混同；缺测被补0 |
| 状态与原子性 | 状态初值、一次操作的提交点、失败后状态、重放及重试结果 | 前两条已入库第三条失败；失败批次ID也被占用 |
| 错误 | 可判定类别、条件、错误优先级、是否回显、成功/失败响应 | 多重错误每端返回不同码；错误响应泄露原始载荷 |
| 版本与协商 | 请求版本、接收支持集合、精确匹配、未知版本、回执版本、转换政策 | 把不支持版本当旧版解析；声称兼容却默默丢字段 |

确定性小型协议宜先选择清楚的拒绝/接收行为，再评估宽容解析是否值得额外歧义。严格解析不自动更安全或更好，应记录输入兼容代价；不同语言是否能实现严格行为需真实组合验证。

保持稳定条款ID独立于章号。每条规范要求应能沿“原材料位置→选择理由→条款ID/版本→方法→输入和初始状态→预期→现有证据”反查。资料性解释可给意图，不能暗中增加实现者义务。候选技术数值不因写入“应”而成为法律强制要求。

## 3. 先写验证方案，再决定结果能说明什么

对于数字接口，字节比较、解析检查、状态观察和互操作通常比物理测量合适。未测时延/精度不编校准记录和不确定度；如果提出时延等测量要求，必须另给起止事件、样本、环境、设备/校准、重复性和判定规则，不能拿功能用例替代。

可执行方案至少给：对象与版本、所用文件和哈希、运行方式、一次运行的初始状态、输入字节或确定生成办法、执行步骤、预期响应、预期状态、失败保留方式和覆盖边界。避免依赖有歧义的伪JSON；重复键、BOM、无效UTF-8、尾随字节和超长边界应保存原始字节或生成规则。一个向量包含多个错误时按正文的错误优先级给预期，不把解释器默认异常当协议规范。

### 3.1 最小覆盖的选择方法

不是固定要凑多少用例，而是每项可失败要求必须有观察办法：

1. 对每个区间检查端点及相邻非法值；字节上限用合法短消息补JSON允许空白至精确上限，再多一字节，避免其他错误先触发。
2. 同一数值用整数、浮点、布尔、空值和非有限表示测试，检查规范实际允许的集合。
3. 序列、重复键和未知字段单独检查；状态用连续调用证明原子提交、失败不变和重放处理。
4. 版本至少覆盖支持、不支持、未知格式和旧新组合；指定所选版本的响应不能由测试工具默改。
5. 对所有拒绝分支检查无载荷回显，以及是否留下记录/批次状态。断言只验证响应码不足以证明原子性。
6. 保留最强正反对：说明所选方案比备选消除什么分歧，又增加什么转换/迁移成本。

### 3.2 按实际来源区分验证证据

| 证据 | 可写结论 | 仍需的后续证据 |
| --- | --- | --- |
| 既有记录的hash、字节、预期／实际值及状态连续性复核 | 指定记录内部一致，并与所核版本／输入相符 | 不是本次执行；真实执行条件、方法独立性和正文忠实性仍需核 |
| 草案示例/参考模型与既定向量比较 | 这些输入在该模型/方法版本下符合预设期望；未执行时只有方案 | 模型对正文的忠实性审阅，独立实现和产品条件 |
| 同作者不同实现的实际双向交换 | 本次发送端×接收端、版本／配置及字节下的接收、拒绝与状态观察 | 不因不同解析器、语言或进程自动获得独立性；共同设计误解仍可能存在 |
| 两个独立实现互发及共同对照 | 有独立性依据且实际执行的发送端×接收端、版本和配置组合可互通 | 未测实现/平台/边界不能推广；真实性能另测 |
| 有权专业符合性/认证结果 | 仅按其范围、对象、规则和有效条件引用 | 内容/环境变更后的适用性复核；组织批准仍分开 |

同源模型开两个进程不算独立互操作。工具返回“passed”不是专业认证；引用历史记录时保留原执行日期、对象和范围，本次复核日另列。既有失败、未执行和不适用分开，不能把重新统计304条历史记录写成新跑304次，也不能只改版本号搬用旧结果。

### 3.3 从同作者记录恢复到独立实现验证

先从给定需求决定必须观察的状态及故障范围，再确定当前材料能覆盖哪部分。需要独立互操作时，取得实现方及独立性依据、实际产品／构建版本和哈希、发送／接收接口、版本／配置、初始状态与重置方式、输入字节和响应／状态记录通道；代码未互相导入或进程PID不同，只证明这两项事实。未经验证的实现仅列候选，不把厂商名称代替独立性证据。

冻结每个发送端×接收端组合的步骤及判据：合法与非法输入、同版和混版、完整拒绝是否保持状态、重放／重试、顺序和空值含义。期望来自给定要求并接受方法审阅，不从被测端返回值生成；状态链传递实际观察，不能将预期状态回填后声称接续成功。保留实际字节、hash、初始／前后状态、环境、失败和清理范围；超时或来源不符按预定停止条件处理，不重抽成功记录覆盖失败。

[River给定需求R10](river-demo/requirements.json)限串行内存，未实现重启持久化、事务／并发、断电／磁盘故障和确认丢失。本案先验证这个范围内的版本、整批、重放与新进程作用域；新进程空状态再次接受旧批次是作用域观察，不是耐久去重。需要生产持久化、并发或性能时，先由技术责任人明确用途、状态寿命、故障模型和判据，再扩方法及实现，不凭“可靠”补阈值，也不把范围外未实现项改成当前向量失败。

[已有双进程记录](river-local-interop/verification.md)与[12项专业待审问题](river-review-readiness/review-pack.md)可作具体交接基础。独立实现未到位时，交付当前已能确认的正文／矩阵、独立试验待填的具体实现条件与SQ04恢复材料；不新造第三个同作者接收器、不填结果，也不因此停写已知条款。

## 4. 相互冲突的意见要改变具体文句

建立原意见ID、针对版本、提出者及代表权限、内容、证据、建议、理由、原/拟条款、验证/程序影响和有权决定状态。重复意见保留各自来源；一名供应商的“大家都同意”不是共识。

意见建议必须作出有理由的取舍。例如“允许一切未来版本”可能降低升级阻力，却使接收端无法判断空值/排序等新语义；可建议拒绝静默降级，同时保留部署前能力约定或显式转换的备选，写清谁承担验证和信息损失。没有时延依据时，拒绝填造毫秒值；说明什么业务需求、测量方法和样本能使意见恢复审查。

技术、编辑、程序和IP意见分开。将字符串错字改对可能是编辑；删除异常条件、改变数值或把“宜”改“应”是实质变化，不能因修改量小就称勘误。仅取得目录的引用先保留原版的实际已知依据，不把新版当作已读全文。

有可用组织规则时列其实际材料、程序条件及角色；未核事项具体标缺件。不用虚构统一票数、期限、申诉流程或重大变化重征门槛补齐。组织规则明确的动作不一概退成“请咨询”：列触发事实、规则位置、谁执行、当前尚缺什么。所有处置先是建议，除非有对应有权决定记录。

### 4.1 新增来源的局部恢复

新取得勘误、目录、全文、许可或组织回复时，保留旧来源及读取范围，记录此次取得时间、官方位置、原发布日期／生效日、实际内容、适用对象和用途权限。分别决定“读到了什么”“内容或状态改变了什么”“谁有权采用”“哪些产物受影响”；读取成功不能自动关闭意见或升级符合性。技术判断与组织／披露决定各自给责任角色。

收到SQ09组织／类型／阶段和实际回复后，核其文件版本、决策权限及针对的问题；接受、部分接受、拒绝、待决须有具体理由和相应拟文。收到SQ07材料许可只能恢复获准用途，不连带批准SQ11外发；收到独立试验材料只恢复其实际观察，不代替组织批准或专业签核。只有对应问题的依据、权限和受影响产物都已核对，才记录该项实际处理状态；其他SQ及旧失败继续保留。

## 5. 修订稿必须能单独实施

完整替换稿重写范围、定义、每条受影响及不变的规范要求、异常/版本行为和方法，不只说“其他同旧版”。稳定ID不变不代表语义未变；列旧/新条件、原因、技术/编辑分类及受影响向量。

沿以下链逐一写影响：条款→解析/状态/错误→方法和向量→已有结果→发送/接收实现→文档/下游注日期引用或合同→组织意见/审查→外发支持与权限。旧版本的成功记录保留为历史，不变项可作为背景，不能复制成新版本整体通过。新结果只能绑定实际运行对象；未跑的替换稿仍是计划。

给并存方案和退出条件：可各保留旧新版本入口，以明确版本值选择，不静默把新语义塞入旧标签。改变序列或缺测含义时，机械回填、重编号或降级可能丢失语义，必须另有转换规范、使用方确认与验证。生效日、旧版废止日和强制迁移期限只能来自有权决定；内部提议可写条件顺序，不造日历日期。

引用更新先取得合法全文并比较，不能因标题含“新版”就改为不注日期；注日期合同保持其实际约定，是否变更交合同责任人。按组织已核程序准备修订/重征材料；若是否属于重大变化的标准未核，应交组织角色确认该判断，同时保留已能确定的正文/验证工作。

## 6. 两条IP交接和三个交付部分

IP-保护：逐拟公开条款/附录标新增技术或组合、既有公开、目标地区、实际申请原件及提交回执、支持疑点和预定公开事件。单个申请号、不同文本的A与B分别出现，不能证明A+B组合获得支持；缺支持只阻止对应外发，内部候选仍可完整写明。

IP-权利：将标准条款/实现/备选、声明原件及权限、权项/状态/地区、组织专利政策全文和许可文本交RIGHTS，分别审必要性、FTO、许可及竞争疑点。声明人声称“必要”或“免费”不是审查结论，不代签许可承诺，不将所有标准都强制改成专利先申请流程。
