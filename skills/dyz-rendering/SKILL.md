# 安全预览与渲染证据

## 按任务加载

按[共用读取顺序](../dyz-workbench/SKILL.md#读取范围与差异优先)定位实际文件、异常与变化，再补必要原文；完整报告保留，省略项不算已检查。调用Word回查时优先按[精简返回说明](resources/docx-readback.md#可选精简返回工具14)取有界差异与异常索引，再按报告位置补读。

- 先按下文区分静态、screen与print及缺陷责任。
- 开始专业图文审阅前，读[检查清单](resources/review-checklists.md)中对应业务；复杂图/Word/PDF/print只读适用格式行。
- 只有文字/局部资料时，可参考[静态报告示范](resources/examples.md)。
- 收到编辑后的DOCX、要核条款身份或隐藏内容线索时，读[编辑稿回查](resources/docx-readback.md)，按实际字节列书签、文字变化及跨部件修订／批注／隐藏标记；标记清单不等于隐藏内容已清理，不能给原生成清单换hash沿用旧审核。
- 生成预览、实际浏览器观察或绑定旁证前，读[工具与证据步骤](resources/tools.md)，并遵循当前工作区浏览器策略。工具需Python 3.11及同包tools；单独Skill不能运行。

关联CORE-07、FIG-05、REVIEW-07和相应AC，WP-02/04/05/06/07。官方Word/PDF、物理打印及专业制图适配仍未验证。

## 先确定用途和可检查范围

接到“看看图对不对”“材料能否打印”“帮我检查文稿”时，先读用户要求和获准材料清单，再选择下面的检查路线；不默认启动浏览器，也不把生成HTML当作完成审阅。输入尚未获准进入宿主时，先回共享权限预检，不为检查收集私人原件。

| 请求与证据 | 本次可以做的事 | 不能据此给出的结论 |
| --- | --- | --- |
| 只有正文/图号/源码文本 | 静态比较内容、引用、条件和连续性，列出待视觉观察项目 | 字体未裁切、页面未溢出、真实截图一致或打印合格 |
| 有当前源稿和获准预览环境 | 明确视口/语言/范围后进行screen检查，记录实际覆盖段落/页/图 | screen通过不代表纸张尺寸、页边距和物理分页合格 |
| 要求打印或正式文件格式 | 先取得用途、实际输出文件、纸张/字体/模板规则与获准排版工具，再定print检查计划 | 当前screen渲染器不能提供正式Word/PDF或官方接受证明 |
| 只有局部截图/旧预览 | 仅记录可见部分和版本未知项，要求当前源及必要剩余范围 | 未观察区域、其他字体设备、旧版本替换后的全稿通过 |

### 入口步骤与最小产物

1. **确认对象。** 列明源稿版本、正文与图/表/附件关系、工作稿或冻结候选、用户要查的具体问题。只查图号时不扩展为专业内容重写。
2. **确定用途。** 区分阅读、内容核稿、屏幕显示、打印和正式格式准备。只有当用途影响检查时询问尺寸、语言、长页或规则；不要为了静态文字比对索取全部设备参数。
3. **声明证据。** 分列已取得源文本、HTML、截图、实际浏览器观察和打印文件；未取得就是未取得。截图由谁、何时、对哪个版本产生也须记录未知。
4. **制定检查范围。** 静态范围列所比较段落/图号及依据；screen范围列实际视口/media及覆盖页图；print范围列规则版本、页面和物理参数。长页不能用首屏代表全文。
5. **先交可执行部分。** 无浏览器可做静态差异和检查计划，不必停掉全部任务；正式打印条件不足时明确阻塞，不能拿纯文本或PNG替身放行。
6. **交缺陷与恢复条件。** 每项写位置、源/目标版本、观察事实、影响、归属和复查方式。专业语义有变化交原业务确认，别以“修排版”为由删条件或改变数值。

最小报告交任务/用途、材料/版本、已执行范围、缺陷（位置/依据/影响/接收者）、未检查/不适用理由及复查条件。

涉及文件接收时，**隐藏信息单独列状态**：修订/批注、隐藏文字/图层、附件/嵌入对象；未得实际文件不能推定不存在或不适用。按[复杂格式清单](resources/review-checklists.md)列获准副本、适用工具与检查责任作为恢复条件；不为补报告启动软件、宏/外链或索要真实受限材料。静态差异与实际视觉观察分别报告。

### 缺陷归属、修订和复验

缺陷表固定记录：ID、业务、源/目标版本、位置/覆盖、证据类别（静态直接对照/实际观察/他人记录转述）、事实、影响、建议、责任接收者、阻塞范围与复验条件。严重性按实际影响说明：例如例外丢失会改变适用范围；不要用装饰分数抵消语义/秘密问题。

1. **内容错误/不明**回patent/software/standards及技术负责人；保留两个版本与来源，待业务确认后修改。原源就错不能只改HTML，否则下次导出又错。
2. **版式/生成错误**回生成/排版层；以获准源为依据修复裁切、折行、标签位置，不改变专业语义。复验问题处及共用版式影响范围，例如同一表格规则影响的全部页，而非只截一张修好图。
3. **证据缺失/版本不符**回采集与保管方；提供待采版本、文件、视口/media、页图范围和字节要求。不能用路径/附件名称算图片哈希、重绘替身或给旧截图改版本号。
4. **复验闭环**保留原缺陷与旧证据；源/包/渲染参数变化后重新生成并绑定实际源、包、HTML/输出和观察。根据变化及依赖列复验范围，未覆盖部分不继承全稿通过。检查事实和专业批准分开，最后只对已执行范围关闭缺陷。

需要print时，另收实际打印输出及规则、纸张、字体等证据，当前screen校验器不接管print放行。复杂办公格式/专业图的实际适配仍待验证；下节给出跨阶段返工文字方法，不解除已有门禁。

### 跨阶段返工：从退回原因到可接收的新版本

输入为缺陷单、旧源/输出、业务确认的修订及既有观察记录；只处理请求的范围，不自动改专业内容。先把每个缺陷标为待确认、已定位/待修、已修待复验或按明确证据关闭；修复者声称完成不等于审阅者已验证。

1. 对照确认后的源和输出，判断错误在哪层。正确源的条件在输出丢失，修生成/导出；源含错误或语义尚未定才退业务。业务已确认的新条件不再任意否定，但新稿的其他专业判断仍不由渲染批准。
2. 区分一次性输出补丁与可重现修复。只改HTML/截图没有更新生成源或模板，下次导出可能复现，缺陷不稳定关闭；先修拥有问题的源/生成规则，再由当前获准源重新生成。不能直接修截图来证明源正确。
3. 沿同一模板、字体、表格样式、图元或分页规则追踪影响，列问题位置和所有受影响页图；局部修复复验不得冒充全稿。跨稿件引用也核版本，未受影响内容保留但不伪造新的观察。
4. 对新产物逐级保留实际源/包/渲染器参数/输出与证据关联；未取得字节不填哈希。旧源或旧包的审核和截图留作历史，不换标签迁移；先做静态语义比对，再按所需media执行screen/print，缺环境只交复验计划。
5. **接收与批准分开。** 每项核正确内容已确认、新输出对应、影响范围已检、证据同版及剩余未知；分别报告：
   - 专业确认、生成修复、screen/print观察、版本/证据接收的状态；收到或接受版本证据不等于批准交付。
   - 候选包版本/范围、拟动作、对象、用途、渠道、有权批准角色及批准状态。未知交权限负责人核确认与恢复条件，可跨段关联；“内部稿/未发送”不能代替批准状态。
   - 专业变化回原业务，视觉问题由实际观察关闭，具体行动交workbench核定。无浏览器可交静态发现，视觉项保持未验证。

**合成返工例。** 四张表共用模板；F1为旧表1裁切，作者仅改HTML并声称局部截图已好。业务确认v2新增“检修模式除外”，源有、导出清单无。F1标已声称修复/待复验且需修模板；F2标静态发现导出丢例外，回生成层，不要求业务撤回正确例外。修模板/导出后从v2重生成，静态核所有受影响条款，screen核四表及相关分页，print未执行单列。旧局部截图/包审核不能作v2全稿通过；未见截图就只引用作者陈述，不报亲自观察或填截图哈希。

**上述返工例的交接补项。** 本次候选是从v2重生成的四表及关联输出，当前尚未取得新字节；专业确认仅覆盖题给例外，生成修复和screen/print复验尚未完成。版本/证据接收无记录，交付批准未知。后续包范围、对象、用途、渠道及批准角色由材料/权限负责人核；已有业务确认不能迁为交付批准。实际文件到位后，还须检查修订/批注、隐藏层及附件，当前标未检查。

## 交付前检查

- **范围：** 源/目标同版，实际覆盖段落、页图、视口/media与证据对应；首屏不代表全稿。
- **隐藏内容：** 文件接收涉及的修订/批注、隐藏层、附件和嵌入对象有已检/未检/有据不适用状态及恢复负责人。
- **返工：** 内容问题回业务，生成问题修源/模板；重生成后查同模板影响范围，不修截图冒充修复。
- **接收：** 专业确认、生成修复、视觉/打印、版本证据接收、交付批准分别记录。真实截图未取得不编哈希；行动未知不阻止有依据的静态报告。
