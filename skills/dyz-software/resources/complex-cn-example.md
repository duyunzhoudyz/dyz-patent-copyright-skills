## 3. v1.1使用与设计替换说明

软件以UTF-8 JSON记录数组为输入，转换为CSV文本；提供cli.py命令行和api.application这个WSGI调用对象，两入口共享core.py。无GUI、内置HTTP服务器、鉴权或数据库。本稿按Python3.11标准库源码静态整理，未运行以下命令，不声称网络部署、性能或所有平台已经验证。

核心输入最多1000条，空数组合法。每条包含id、label、value：id和label是去首尾空白后非空的字符串，但实现保留原字符串；value为非负整数，布尔值和浮点不符合。输出列固定为id,label,value，保持输入顺序，空数组仍有表头。

v1.1无论strict是否开启，都拒绝完全相同的重复id，错误类别为duplicate_id，不去重后继续。默认strict关闭，额外字段被忽略；开启strict时，字段集合必须恰为id、label、value，额外字段产生unknown_field。strict只控制额外字段，不切换重复id规则。

CLI在同版core.py、cli.py相邻的目录调用：

```text
python cli.py records.json result.csv
python cli.py records.json result-strict.csv --strict
```

操作者须使用有权读取的输入和有权写入且尚不存在的输出。参数--strict来自v1.1，不适用于旧版CLI。成功退出0；输入内容错误退出2；目标已存在且输入已通过时退出3；输入或输出I/O故障退出4。CLI先完成输入校验并生成文本后再独占新建文件，因此内容校验失败不创建新目标；输出写入发生I/O故障时可能留下部分新文件，不宣称原子写入。

WSGI入口只接受路径/convert及POST。v1.1允许空查询串、strict=0或strict=1，最后一种开启strict；其他查询串返回invalid_query和400。内容类型为application/json，正文长度和流检查沿源码执行，API容量上限65536字节。合法请求返回200及UTF-8 CSV；invalid_json返回400，其余到达core的数据校验错误，包括duplicate_id和unknown_field，返回422 Unprocessable Entity。路由、方法、内容类型、长度等前置错误仍按对应分支返回，不能将所有错误一律改成422。

| 静态情形 | CLI结果 | API结果 |
| --- | --- | --- |
| 两条id完全相同且其余有效 | duplicate_id，退出2，不创建新目标 | duplicate_id，422 |
| 默认模式有额外字段且其余有效 | 忽略额外字段，成功退出0 | 空查询串或strict=0时成功200 |
| strict模式有额外字段 | unknown_field，退出2 | strict=1时unknown_field，422 |
| 不能作为JSON或UTF-8解码的正文 | invalid_json，退出2 | 到达核心时invalid_json，400 |

本次新增的组织为核心严格字段/重复检查、CLI参数传递和API查询及错误分流。字段顺序、CSV表头、内存转换、无GUI和CLI不覆盖已有目标等既有事实可依当前字节复核保留。这里描述功能不主张对所有同功能软件的排他权。
