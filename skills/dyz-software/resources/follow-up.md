# 软件补正、变更、跨地与争议

收到补正/变更/继受、局部版本修订、跨地区或版权争议任务时，先读对应小节。 返回[技能入口](../SKILL.md)。

## 补正、变更与继受：逐事项编辑闭环

本节为SW-06文字方法，只有收到相关任务才进入，不因一般版本更新自动办理登记程序。先读通知/事件依据、实际已提交材料、当前内部稿、技术/主体确认材料及旧审阅；分开登记事项纠错、产品升级、更名、权利继受，不能将内部最新软件直接替换已提交对象。

1. 核通知真实性/合成身份、页数及附件、案件/软件标识、送达证据和适用规则。稳定Q编号逐项摘录要求及其针对材料位置；无通知的变更/继受不虚构Q项，期限未知交软件程序负责人核，不套专利OA期限。
2. 对每项列“原提交值—通知问题—新证据及确认者—候选值—替换位置—影响”。事实冲突保留并列，日期、作者、主体不能为凑齐表单推断；完成/发表/签约/登记时间分开。许可或付款不是当然转让，合同范围需对具体版本与表达，旧版合同不自动覆盖新版。
3. 起草逐项补正回应和可独立阅读的替换标题/段落/字段；说明为何采用该值及仍缺材料。受影响文件给清洁稿和差异映射方案，保留原提交副本。新增功能/版本、范围或权利人变化另列路线候选，核能否在本程序处理，不把升级冒充笔误。
4. 沿scope/rights—选材—秘密处理—说明/表单—渲染—具体包逐项核影响。技术负责人有依据确认代码未变时，不强制全量重选；但名称/版本映射、材料元数据和关联审核仍核，不能以代码不变直接继承整包批准。新秘密处理或选材区间变化需重建对应映射，未知未读字节不声称已重建。
5. 复核Q项覆盖、候选值一致性与来源；旧审阅保留作历史，受影响项交相应角色重审。交付回应稿、替换稿/清单、来源/差异表和内部问题单，私有审计独立留存。
   - 局部说明/选材修订同样区分正文候选、内部权利/选材问题、行动条件；问题附接收责任、阻塞步骤及恢复条件。
   - 行动条件绑定当前候选版本/范围、动作、对象、用途、渠道、有权批准角色及状态；未知逐项待核，不用源码用途权限或登记路线判断代替交付权限。
   - 写明谁核有权主体、所缺确认和恢复条件。可以跨段关联，不强制表式；未知只阻止对应行动，内部有依据修订可继续，不重做无关内容。
6. 有权人员确认规则、事实、当前版本及具体行动后才另作固定包批准；发送/正式接收/登记结果需真实回执独立记录。结果不明先核实，不重传或称补正成功。补证仅关闭其覆盖的问题，不全局标已批准。

**合成补正示范。** 训练通知N的Q1说标题不一致、Q2缺失败说明；提交表为“云岸整理器1.1”，说明写“云岸1.1”。T确认正式名为云岸整理器1.1，失败返回5、不生成新输出，源码未变；送达未知。回应Q1候选：“依据T，说明标题拟统一为‘云岸整理器1.1’，不改变本次软件版本。”回应Q2候选：“补充失败路径：输入校验失败时返回5且不生成新输出；本段依据T静态整理，未新增运行证据。”两段是内部候选，正式可用性待核。

替换标题/段落如上；问题表定位旧说明两处及A旧审阅受影响，源码无需凭空重选但须核名称关联。若客户顺便要2.0，单列升级对象/规则问题，不借补正替换1.1。恢复需完整规则/送达及有权审阅，不能算期限或填已登记。

**合成继受示范。** 口述“甲已转给乙”，合同仅许可v1、拟变更对象为v2：工作说明写“现有许可摘要不证明v2权利转移，拟主体变更尚待依据”；请求版权负责人核范围、转让/继受事实、签署权限及登记路线。可以整理主体/版本链和变更候选，不填乙为既定权利人、不用合同日期代完成日；无通知不编补正事项。

## 跨地区保护/登记与版权争议专题（SW-08）

### 按地区和路线形成材料差异，不复制登记结论

从当前软件/版本/表达范围、主体和获准用途起步，逐地区分别问“是否存在本对象适用的登记或其他记录路线”“保护/权利主张依据是什么”“为哪种用途准备何种材料”。登记路线不适用不表示不存在保护；没有规则是未知，不是不适用。CN、US及其他目标分别核官方来源/版本/对象/生效范围，不能统一套中国页数或将一地记录当另一地确认。

1. 固定共用事实底表：本版/既有/第三方/AI辅助、权利链、完成/发表事实、用途权限；只共享证据引用，不共享专业结论。地方规则或用途变化只使关联材料待重审。
2. 逐地读获准的要求/例外和许可，建“要求位置—拟用本版材料—缺件/冲突—可复用/须改—负责人”差异表。选材、遮蔽、表式、语言、身份/代表及日期分别核；没取得源码就不报行数，缺要求就不填常见格式。第三方仅本地阅读时不得因另一地要求而自动选入交存。
3. 实际给当地内部说明段落和材料候选清单，不只是JSON；规则未知的部分标待核，仍可写已有事实。翻译权限与读取权限分开，新增表达/公开范围再经原专业审查。
4. 交付共用事实表、逐地差异/缺件、各地候选稿、内部风险/私有审计；具体包、接收对象、用途、渠道与批准另核。不把一地批准改名为全球可交；无发送记录不声称已登记。

**合成例。** A规则仅要求本版表达清单和操作说明，B明确对本题对象无该登记路线，C规则缺失。表分别写A准备清单/说明且页数待核、B本登记路线不适用但保护问题另审、C路线与材料未知。正文候选：“本稿描述W2的自主表达及操作；第三方插件仅许本地阅读，暂不列入交存候选。”不填总代码量，不以A稿覆盖B/C，也不虚构版权登记证明。

### 争议证据：表达、来源、接触与替代解释

先明确请求为证据准备还是地区专业判断，冻结左右软件/版本、具体表达与取得方式。只读获准节选/源码，不执行或越权取证；保留原件、来源链、取得时间和实际哈希（有字节才算），摘要和口述不冒充原件。时间戳/哈希只证明所记录关联，不认证创作或权属。

- 按位置逐项比较功能/思想、接口约束、既有/公共/第三方、拟主张自有表达；不能把共同功能或共同依赖当自有表达复制证据。分类不确定保留，而非为了提高相似度全纳入。通用短语的可保护性另核。
- 对候选表达记左右原文/位置/版本、相同与差异、来源/时间、人类创作与权利依据；没有读到右方内容就是未观察，不标不存在。字面匹配是线索，不以比例阈值、变量换名或专利逐要素矩阵判侵权。
- 建接触与来源时间线：何时可能接触什么、证据为何、是否授权、是否有独立创作记录或共同来源等反向解释。接触未知不编接触，发现共同来源也不无依据清除其他争议。
- 实际形成审查摘要、比较/排除表和补证计划；法律/版权人员审保护范围、实质相似及规则，技术人核版本/实现，取证负责人核合法保全。内部调查线索与可对外出具文字分开；不得为取证侵入系统、传播源码或擅自对第三方发函。

**合成例。** L第5行/R第9行同用第三方函数parse(x)，且都按日期排序；先将公共调用与功能分列，不作为本方独创表达依据。两方同有“请校对输入后继续”的提示，只列待审表达候选，通用性/来源/独立创作未核。L注释只听说R也有，R原件未见，记未观察。摘要候选：“已见公共依赖和功能相似，提示语为待核线索；现有摘录不足判断复制或侵权。”补证清单给获准原件/版本、创作过程、权利链和接触时间，每项写责任及恢复条件，不猜结论。

**补正/局部修订的交接示范。** 上述训练通知的候选包仅含1.1标题和失败段修订；Q1/Q2依据、旧审阅影响及期限问题留内部。技术确认T只证明题给名称/行为，不是有权提交批准。实际接收对象、用途、渠道、批准人/状态未给，材料/权限负责人补齐后才恢复对应传递；送达/规则交软件程序负责人核实。v2升级请求和继受疑点另案准备，不能混进本次1.1补正候选。
