# CN软件版权核心材料方法

适用于中国软件版权材料候选的首次准备及版本变化，尤其是同版发布的CLI/API与共享核心。关联SW-01/07/02/03/04/05、WP-06；正式补正、变更和继受另按[后续任务](follow-up.md)进入SW-06。返回[技能入口](../SKILL.md)。完整实际合成材料见[港湾记录整理器](harbor-example.md)；本轮官方来源、核验日期、条文位置及未核事项见[CN规则证据](../../../references/jurisdictions/cn-software-evidence-20261101.md)。

填写R11材料字段时，另读[2026-11-03公开指南补核](../../../references/jurisdictions/cn-software-guide-20261103.md)、[原1.2字段候选](harbor-delivery-v1.2/form-candidate.md)及[当前1.3字段候选](harbor-delivery-v1.3/form-candidate.md)。2026-11-03曾取得公开所需文件、填表说明与问答；2026-11-08重新取得所需文件，填表说明当次抽取失败，历史取得与本次可用范围分别保留。登录后交互字段、上传限制、正式表式及个案专业适用性仍未验证。需逐行核字段、继承／贡献和补证责任时，读[专业待审包](harbor-review-readiness/review-pack.md)及下文“字段补证与局部恢复”；包内方法可独立使用，不依赖开发台账。

本方法解决如何形成可审阅材料，不认定权属、独创性或登记接受。规则证据与软件事实分别使用：条文决定需要核什么，实际版本和材料决定能写什么。材料缺口只阻止它影响的结论或动作；已获准且有来源的使用/设计正文继续完成。

## 1. 从交付对象决定表达范围

先固定软件名称、版本、功能边界、发布包、入口与组件关系，再提出拟主张范围。CLI和API调用相同核心并随同一版本共同发布，支持将其作为一个关联工作范围；若API有独立发布、用户、版本、合同或独立表达，拆分是备选。进程数量、目录位置、行数、是否联网均不能单独决定软件数量。

范围取舍至少解释三点：本案为什么合并或分开；选择会留下什么表达或权利缺口；备选需要改哪份事实/材料。不要为了避开合同冲突，把API从代码清单删掉后仍用“含API的完整软件”名称、功能和一般交存结论。允许先交内部子集，但名称应表明这是工作子集；若拟变更登记对象，需技术负责人确认它确为可界定的软件/版本，版权人员确认路线并同步说明、表式和选材。

把表达候选落到文件、函数、段落或具体组合，而非“数据转换”“REST接口”等功能标签：

| 层次 | 可写的分析 | 不能从中推出的结论 |
| --- | --- | --- |
| 功能、算法思想、约束 | 说明输入校验、字段转换、接口兼容的目的和限制 | 排除他人所有同功能实现、算法或数据格式 |
| 本版具体表达 | 指出实际源码、异常分支、组织组合及说明文字的位置，列拟主张部分 | 仅靠行数或功能复杂度认定独创性 |
| 既有/第三方/生成表达 | 分列来源、版本、改写范围和所需通知；不把依赖API名称归为自有表达 | 许可使用等于权利转移，或一行第三方引用使整个软件没有保护 |
| 人工与AI辅助贡献 | 对具体段落核人工选择、改写、组合和记录；结论留给适用规则及专业审阅 | 伪造人类作者或一律认定全部有/无保护 |

## 2. 把贡献、权利和动作权限拆开判断

对每个组件并排写：谁提供何种表达、何时纳入哪版、支持材料、相反材料、拟主张/排除、允许的动作。署名、雇佣、付款、交付、仓库作者与版权归属不是同一事实。职务核任务/职责和适用条件；委托核书面约定及实际交付范围；合作核可分割表达及共同约定；旧版许可或转让核是否覆盖本版新增表达。书面合同与摘要冲突时保留两者的位置，不把摘要当定论。

权限至少分本地处理、交存、特定外部审阅、云端处理、公开发布。已有内部准备授权足以继续内部稿；只有本地阅读权的组件不得因同属发布包自动选入拟交存材料。对真实资料还须先确认宿主及工具路径；本示范的模拟权利事实不改变实际演示代码的项目许可。

有效输出不是一张“全部待核”表。对已足够的事实作具体建议，例如“核心和CLI按模拟职务材料列为本版拟主张候选；API保留在软件功能说明中，但委托权利与交存许可未解决，暂不形成完整交存候选”。并给版权负责人需要核的具体条款/版本及恢复条件。

## 3. 以实际字节建立两段映射

先冻结显式获准源文件清单，不递归采集不明目录。每个文件记录相对路径、组件、实际版本、编码/换行、字节数、SHA-256、实际物理原行数。哈希绑定字节，不证明创作时间、身份或权属；清单中的总行数只覆盖清单，不是整个产品的官方源程序量。

区分三种量：

1. 物理原行：按已说明的解码与换行算法统计，含注释、空行与尾行处理。本案可采用UTF-8解码后的splitlines()；报告该算法，不能拿这个数证明原创性。
2. 选中去重原行：同文件区间取并集后计数；重叠区间只算一次，不因首尾选取重叠而重复增加。选材映射每段保留文件版本、原行起止和选材顺序。
3. 展示逻辑行/页：加入页眉、行号或长行折行后的展示结果，独立记账。一个原行可对应多个展示行；不得反推源程序变多。未实际排版就写未生成，不把浏览器高度或屏幕截图当正式页数。

第一段映射为“文件哈希＋原行→选材片段”；第二段为“选材片段→实际输出行/页”。给每个变换记理由：直接复制、遮盖、换行、页眉等。源文件不改；正文中不得插入说明性伪代码当源程序补足量。注释/空行可在物理计数中存在，但能否计入目标材料格式及程序量另核。

逐文件的全区间清单也应可重建：固定文件顺序，给累计选中区间，实际导出后核首末行和跨文件接缝。若秘密使某行不可外传，内部映射只留受控位置和处理状态；公开问题表不重复原值。SW-02/03若实际执行，工具结果与这份映射对照；没有执行就不能写“已通过”。

## 4. 分别选择一般交存、例外交存和封存

依据本轮规则证据所列《计算机软件著作权登记办法》第10、12、13条，先分别制作目标版本源程序与所选文档的完整分页母本，再判断应交全部还是适用前后段。文件清单、屏幕预览和工具逻辑页都不能直接代替这一步。

| 路线 | 本案选择依据 | 代价和停止条件 |
| --- | --- | --- |
| 一般交存 | 实际应交存的程序及所选文档区间已完成用途权限和秘密审查，无需遮盖；依法判断前后段或短材料全部 | 短程序应交全部时缺范围内API等组件，或应交存区间被删/遮盖，不能称一般交存齐备；长程序依法选取首尾段自然未含中间组件不当然缺件。不得补行凑页 |
| 例外交存 | 确有需保护的内容且适用第12条具体方式；列所选方式、涉及原行、适用条件和理由 | 不能仅写“脱敏即可”。覆盖上限针对交存源码，不是删除权；固定页数组合对短材料如何适用须核，不能把未核方案标为可受理 |
| 封存申请 | 对源程序、文档或样品有另行封存需求，依第13条提出申请候选 | 封存不等于免交存、无需权利证明或普遍不公开承诺；现有秘密数据的处理权仍需核 |

第10条本轮核得：程序和任一种文档分别前后各连续30页；各自不足60页交全部；除特定情况外程序每页不少于50行、文档每页不少于30行。第12条的三种选择、遮盖方式及上限以来源证据原位置核对；不要从“各连续30页”推得必须把短程序造到60页。文档与程序分别判断，不以二者总页数合并达到门槛。

第12条第一种方式的50%分母是实际交存源程序。本轮所读条文未给按字符、行或面积计算的技术口径；内部可以列自定测量口径，但不能据其自动宣称合规。末页、含图页及所谓“特定情况”也不自行创设豁免。

若正常案没有秘密且程序很短，选择全量映射与完整文档作为一般路线候选，有明确理由，不必为了展示复杂度强行例外。若冲突案的API只有本地处理权，当前可做全范围静态说明与有权部分的内部选材，不足以交存原完整软件；可比较补权限、变更软件范围、适用例外/封存三条候选，且说明例外/封存不治愈权利缺口。中国版权保护中心在线指南/表式未能核验时，只把对应操作要求留待核，不否认已核法规条文，也不推定在线受理。

## 5. 秘密处理到正文、日志和附件

先识别材料中的凭证、客户信息、未公开技术、保密注释、内部地址及导出元数据。按权限及规则选择排除、替换示例、获准遮盖或特定路线；操作对象为副本。对外稿不得残留遮盖层下面的原文、复制可恢复文本、批注、隐藏附件或指向私有路径的链接。语义秘密需要材料负责人审阅，字面扫描仅是辅助。

使用说明也会泄密：源码某常量已遮盖，示例输出、日志、设计解释不能再次写出。说明可写“由管理员在获准环境配置”，但不能虚构配置机制；若程序实际上硬编码，应在内部问题中说明真实实现和候选处理，正文按当前事实表达而不伪造功能。缺少秘密处理授权时可继续编写不含秘密的使用正文，但不得提前生成并外传含原值的包。

## 6. 按行为写完整使用及设计说明

先读当前版本源码与获准帮助/接口/运行记录。区分“静态读取可确认的分支”“所引用他人运行覆盖的路径”“本次实际运行”；某成功例实跑不等于全部平台、错误分支或生产部署均验证。没有GUI就写CLI/API的输入输出，不能为满足材料外观发明登录页、按钮和截图；接口与命令示例是文档，不是运行截图。

使用说明应让读者在已说明的环境中知道如何操作：软件名称与版本、用途/边界、依赖和目录、安装/准备、入口、参数/字段约束、正常输入及完整输出、失败与恢复、已有输出处理、文件编码和限制。API若只是WSGI调用对象，写清无内置服务器，不能编造可直接访问的公网URL、鉴权、HTTPS或并发保障。示例命令必须能对应源码入口，未实际验证的命令标为静态操作例。

需要源码选材、操作取证或截图计划时，按同一操作建立“场景—当前版本/构建—源码分支—可见状态—底层结果旁证—未取得材料及责任”的对应表。成功和失败分别列出；处理失败说明冲突时，也列同一操作的成功对照，才能分辨正常提示与失败误报，不扩大到无关功能。界面提示、列表变化和底层处理结果分别取证，成功提示不能代替成功结果，只有失败截图也不能证明成功路径。未知行为写为待采集的观察对象，不预填结果；用户限制不运行时只交计划，实际采集仍须相应授权，无GUI则使用适合CLI/API的输出与日志证据。

截图或录屏计划同时列明可见信息检查与处理：优先使用合成输入，核标题栏、账号、文件路径及选择框、桌面通知、客户资料和凭证等是否进入画面。已取得的原始证据按权限受控保存，交付副本仅作获准遮盖，并记录处理位置；错误提示、软件版本、操作步骤和结果等必要证据应保留，不以改图掩盖缺陷或伪造行为。尚无图像时写待采集、待检查及负责人，不能宣称已完成脱敏；合成输入也不能代替对实际画面中环境信息的检查。

设计说明解释共享核心与各入口的职责、数据如何流动、何处校验、如何转换、如何返回错误及保存结果。说明为什么同一业务错误在CLI/API有不同表示，而不是复制函数名清单。只写已读到的行为；不推测缓存、数据库、后台任务、持久化或安全机制。异常只列实际处理范围：处理数据错误不意味着能优雅处理所有文件系统或协议异常。

正文旁的来源/一致性表按段落绑定原行与记录，集中列名称、版本、日期、环境、对象范围、字段、状态码和选材量。日期未知的表字段留待事实确认；正文可照常介绍已知软件。实际代码有已知限制时直接写限制，不用理想行为覆盖它。

R11字段先用真实全称、版本及事实形成候选；确认没有简称才留空，不填“无”。依实际申请表统一鉴别材料页眉版本，不能自动增删V或把界面显示当成表值。开发完成、发表和权利事实继续分别核；物理行数不直接填成已确认的官方程序量。确认签章页来自实际业务系统，本项目原创字段工作表不替代它；正文、签章、上传、受理和登记各自留证。

### 6.1 字段补证与局部恢复

收到合同、主体证明、日期记录、交存选择或新规则时，先确认本次要补哪项事实、解决哪个冲突、恢复什么产物；复用已有材料编号、字段与问题ID。按“当前值及来源→新增材料的版本／范围／有权依据→支持与相反证据→候选修改→仍需确认的结论”处理，不把所有字段重新发给用户填写。真实材料先核宿主数据路径与对应用途权限；字段工作表只放获准的必要事实和受控位置，不复制证件号、签名或合同秘密。

| FIELD-18/19：程序量与鉴别材料；办法第9—13、17条、所需文件第2项 | 材料负责人和权利人确认完整软件范围、用途权、程序量口径、所选文档、交存及秘密方案 | 按第3—5节从母本生成对应材料并逐页复核；266物理行不直接填作官方量，一般／例外／封存不治愈权利缺口 |
| FIELD-20：办理及代理；办法第17条、所需文件第1项 | 申请人确定办理人和权限；代理时核当前委托要求，签章及提交确认具体包 | 形成办理信息和行动条件；本项目字段稿不能代替系统生成签章页，未操作不记提交或受理 |

每次补证交付三件具体结果：受影响字段／段落的完整候选替换文、旧新依据与仍有冲突的短表、需要重建及重审的下游清单。没有实际新材料时，只沿上表列缺件与责任，保留已有候选及空值。材料足够支持技术文字时直接完成该文字；材料之间矛盾则保留双方版本、冲突字段与临时候选，不挑有利摘要覆盖原件。补证接受由相应事实或专业责任人确认，作者核对哈希不构成该确认。

内容、规则与权限变化分别追踪。源码不变而权利范围或交存许可变化时，源码字节可复用，选材／秘密方案、字段、交存副本和外发批准仍须重审；只取得身份材料时，不重做无关GUI截图，也不关闭贡献或发表问题。来源读取失败只限制依赖其当前内容的结论，已核历史证据仍按原时点保留。实际替换后调用既有装配／回读方法核同版材料，不能只在内部问题表里宣布已补齐。

## 7. 局部变化以差异决定重做范围

先冻结旧版与新版字节并比较真实差异，再按“变化事实→表达与权利→选材/秘密→说明/表式→渲染→旧审阅”记录传递影响。增加一个参数可能同时改CLI、核心和API错误；仅版本字符串改变也会改变文件哈希。相反，内容完全相同的文件可复用其字节事实，但不能继承新包的整体批准。

保留不变事实并说明依据，例如相同字段输出、目标文件不覆盖、无GUI。已知v1.0允许重复ID而v1.1拒绝时，更新正常边界、失败示例、退出/状态码及设计段；不能只改封面版本。提供可独立阅读的新版正文、旧新位置/理由表、新映射和待重审项。旧审阅仍有效描述它原来审过的旧版；受影响结论不改版本继续使用，亦不把所有无关旧记录抹掉。

内部升级不是正式补正。未取得真实原提交材料、通知、送达和目标规则时，状态是新版本材料准备；SW-06仅交接程序问题，不编补正编号、期限或已登记结果。

## 8. 三类交接必须具体

| 交接 | 应给内容 | 角色和状态 |
| --- | --- | --- |
| 正文候选 | 明确软件/版本/范围的完整使用或设计说明，以及本次实际完成的选材候选 | 技术负责人核事实；rendering接当前字节和检查范围；标静态/引用运行及未做事项 |
| 内部审计与问题 | 事实/权利/规则冲突、源映射、秘密位置记录、旧审阅影响；不默认随正文外发 | 版权人员核权利与路线，材料负责人核字节与秘密，问题逐项有恢复条件 |
| 行动条件 | 具体拟动作、实际文件包/版本、接收对象、用途、渠道、批准角色与当前状态 | 权限负责人核有权依据；内部保存、外部审阅、登记分别判断，发送及回执未发生就记未执行 |

已有内部授权不必反复索取；拟外发条件未知只阻止对应动作。若题目给了外部代办名称但没有批准，不写“交代办提交”；可写“拟向该对象作登记材料审阅，渠道/批准待核，尚未发送”。包变更后重新绑定受影响批准，不把有权读取源码当作提交批准。
