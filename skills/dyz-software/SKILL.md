# 软件版权材料与后续链

## 按任务加载

按[共用读取顺序](../dyz-workbench/SKILL.md#读取范围与差异优先)先读适用方法章节，再读当前主材料；示范、工具字段与历史证据按需要展开，摘要不替代必要原文。

- 范围、权利、选材、说明与一致性：按下文核心链选择需要的步骤。
- 补正、变更/继受、局部版本修订、跨地区或争议：先读[后续任务方法](resources/follow-up.md)对应小节。
- 首次完整材料准备或核对交付形态：读[日志转换器示范](resources/examples.md)。
- CN多组件CLI/API首次材料、版本变化或收到补证：读[核心材料方法](resources/cn-core-method.md)；补证按其中“字段补证与局部恢复”逐项处理，已足够的正文继续交付。需真实字节、完整正文及三案修订形态时读[港湾记录整理器示范](resources/harbor-example.md)。
- CN补正同时涉及旧版受让、新增表达、主体更名或源码争议：读[复杂后续方法](resources/complex-cn-method.md)及[分阶段完整案卷与答复](resources/complex-cn-example.md)；先固定原申请对象，再随补证更新局部结论。
- 美国程序登记、短程序交存、升级/AI与出版变化：读[US材料方法](resources/us-registration-method.md)及[三阶段英文候选示范](resources/us-registration-example.md)，单独核美国作者、主张与交存规则。
- 美国软件表达争议、共同来源和后到反证：读[US表达方法](resources/us-expression-method.md)及[完整比对案例](resources/us-expression-example.md)，按适用辖区核可保护表达、接触/复制证据及排除范围，登记结果不代替侵权分析。
- 确需运行本地工具：读[工具契约与调用](resources/tools.md)；software-intake支持逐项或候选集中确认，discover-software只发现获准清单候选，prepare-software衔接范围/权利/选材，build-software装配完整正文及可选PDF，import-software-manual将Markdown/受支持Word新稿差异纳管后重建。software-batch隔离多项目，export-software按具体文件审批生成本地接收方候选。原图按构建/步骤绑定，完整母本实页检查后才选首尾；缺件继续交内部稿，失败/未审不升级，不为运行工具补造事实或授权。

## 适用边界与依赖

对应 **SW-01至SW-08、WP-06、WP-08软件分支及WP-10适配准备**。触发：软件/版本/组件权属材料、源码交存选材、秘密处理、使用/设计说明、字段核对、登记补正/变更/继受、跨境资料差异、版权争议证据准备。不用于专利新颖性或逐要素侵权结论，不办理真实登记、诉讼、签章、付款、发布或外发。

文字工作稿按专业方法形成；运行工具时须保留六技能、共享`tools/`与实际资源的完整包，单个SKILL.md不能运行辅助工具。Python、模块依赖、输入字段和预检契约见[工具说明](resources/tools.md#运行依赖与调用前检查)。原创代码遵循项目PolyForm Noncommercial 1.0.0及单独商业授权；不覆盖用户源码或第三方材料权利。

## 先确认权限，后读材料

先核本次材料、处理目的、接收方与有权依据；敏感或受限内容进入宿主前，核模型、索引、遥测、工具、日志和子进程数据路径。缺授权时停在读取前，只整理非敏感目录与缺件。取得源码不等于可以交存、公开或送入外部模型。

只读取本次获准的文件与范围，保留原件，秘密原值不进入问题表或日志。后置函数检查无法撤销先前传输；本地Python也不证明整个宿主离线或受控。公开样例和默认测试仍只用合成数据，真实材料不得改标签绕过工具限制。

## 从项目事实到软件版权工作稿

先按下列方法阅读和写作，再把已形成的事实交给[工具说明](resources/tools.md)中的辅助函数；不要求用户先填scope/rights JSON。手工文字工作流也受上面的材料权限约束；工具不能使用时保留文字成果，不手填工具通过状态。核心链关联SW-01/07/02/03/04/05；SW-06正式补正、SW-08跨地区和争议仍按独立任务进入，不为准备说明书自动开启。

### 1. 接任务与读材料

1. 从请求确认要做范围分析、材料准备、单段修订还是审阅；提取交付对象、地区/路线、当前版本、已有公开情况和截止线索。未知地区不妨碍内部事实稿，但阻止确定正式表式、分页或交存接受条件。缺授权则只列非敏感材料目录，不先收源码或证件。
2. 按“产品/架构说明—版本及变更记录—组件与权利材料—获准源码清单—操作证据—旧表单/文稿”阅读。先建立M编号、版本、位置、来源类型和许可表；只读本任务需要且已授权的范围。源码描述不是源码字节，提交记录不是运行或发表证据。
3. 逐事实记录“内容、来源位置、确认者、已知/冲突/推断/未知”。例如README称新版而表单仍是旧版，先并列，向技术负责人问本次拟交哪个构建，不直接全局替换。材料已经说无GUI，就不要追问截图。
4. 最少问题仅针对影响当前产物的缺口：软件对象/版本、组件关系、开发/权利方式、材料用途权限、规则或事实冲突。完成日期、发表日期缺证时分别保留未知，不用Git时间填空。输出任务简报、事实表和带负责人/恢复条件的问题表。

### 2. 形成软件范围和权利候选建议

先画出产品—版本—组件关系：客户端/服务端、插件、共享库、包装层是否独立运行、独立版本/交付、是否同一表达范围，哪些是旧版与本版变化。相同目录不等于同一软件，多个进程也不当然是多个登记对象。

- 同一发布、共同功能且不能独立使用：可先作关联工作范围，说明依据；独立交付/版本/功能明显时列拆分分析候选。混合情形保留两种范围及共享部分，不重复声称公共代码原创。最终登记拆合由目标规则及软件版权专业人员确认。
- 区分功能/算法思想与实际表达；不能把功能清单写成对所有同功能实现的版权主张，也不做专利式新颖性或逐要素侵权判定。
- 逐组件核对开发方式、贡献者、时间/版本、合同或职务依据、既有表达、第三方范围与用途。职务查看职责/任务及适用依据；委托/合作查看交付、署名、权利归属和授权条款；改编查看原版及改编许可。声明只是线索，不能以付款、Git作者或员工身份直接认定全部归属。
- 第三方核对实际版本、许可文本与通知义务及具体用途；AI辅助核对人工选择/改写/组合记录及适用规则，不编造作者，也不一概认定无保护。冲突材料并列交法律/版权负责人，不自行选有利说法。

产物为“组件—版本—拟主张/排除—依据—local_process/deposit/public/cloud权限—建议—待确认者”表。建议可为候选主张、排除、保留通知、补许可、补证或禁止处理。禁止处理的材料不读取；有本地阅读权但无交存权的材料不得选入交存。主张范围建议不等于权属确认。

### 3. 先确定选材依据，再处理秘密

1. 将范围和逐组件用途权限投影到显式源文件清单：文件ID、相对路径、版本、组件、类型、拟纳入/排除、区间及理由。未知目录不递归探测；依赖、生成物、旧版和第三方标明来源，不能改名成原创代码。
2. 核验目标路线当前的选材/格式/例外规则；无规则时给“内部选材方案”，可建议先以获准范围全量建立映射，但不输出通用60页、固定首尾页数或官方接受承诺。排序可采用确定的文件ID/路径顺序并说明，法律要求另核。
3. 只有实际获准字节才能统计：声明清单总源量、原创分类统计、选中去重原行、折行后行数分别列。未提供字节就写未统计；清单不全不称整个产品总量。短程序保留实际长度，不补行、复制代码凑页；缺行先查是否获准排除而非直接补造。
   物理原行含注释/空行的计数不等于官方源程序量或原创性；选中区间去重与折行展示分别记。一般交存要求短程序全部时，排除范围内组件或遮盖后只能形成内部子集/待核路线，不能仍称原完整软件的一般交存已齐。
4. 秘密审查先问可接受的处理方式和用途：不选入、按获准规则遮蔽或转特定保密/例外交存路线，由有权人员决定；不能因“已脱敏”自动获得交存/公开许可。只在副本处理，位置记录到字符/行范围及依据，不把秘密原值复制进问题表、审计或日志。
5. 复核正文、注释、路径、元数据、重复值、示例输出及附件；自动字面检查不涵盖全部语义秘密。输出正文与private_audit分离；未知例外规则只交内部稿。若涉及未公开技术，另交专利支持/公开审查，不以软著登记许可代替。

工具使用时机：范围与权利事实形成后用SW-01/07整理；清单及权限确认后才用SW-02取真实映射；可用秘密处理方案获准后用SW-03。获准完整准备使用prepare-software的固定清单与指纹；其母本完整性仅针对声明清单。主张排除不自动删除交存所需上下文：须分别记录依据、用途许可和非原创身份，未知路线只交内部稿。没有文件或规则不能为了运行工具编造载荷。

### 4. 写使用或设计说明，不写不存在的界面

从材料抽取读者、运行环境、入口、输入约束、处理步骤、输出、失败路径和限制；每节附来源位置。以真实产品形态组织：

| 形态 | 应写的核心内容 | 可用证据与缺件处理 |
| --- | --- | --- |
| GUI | 实际界面入口、控件、状态与错误恢复 | 当前版本真实界面资料；未观察则保留截图待补，不能画示意图冒充运行截图 |
| CLI | 命令/参数、输入文件、输出/退出码、失败是否产生文件 | 源码或获准帮助/日志；未运行时称预期行为，未给定退出码不猜 |
| API | 方法/路径、字段约束、返回/错误、调用关系 | 当前接口/实现依据；鉴权和状态码未知则待核，不随意补默认行为 |
| embedded | 固件/硬件边界、输入输出、触发/时序、异常恢复 | 设计/接口与设备记录；无设备实测不填实验截图或性能通过 |

使用说明按“前置条件—输入—操作—预期输出—失败/恢复”写实际段落；设计说明按“模块职责—数据流—接口—异常”写，不用宣传文案代替。来源不足的章节可标待补，不捏造架构、数据库或支持平台。全部没有运行证据时标static_only；有运行记录也只覆盖该版本、环境和实际步骤，不把引用别人记录说成自己运行。可用SW-04整理事实稿，运行软件须另有授权与环境。

### 5. 核对、修订与交接

将软件名称、版本、日期、环境、组件范围、输入输出、真实源量/选材量和说明/表单逐项并排，写明来源和冲突；提出候选修订及理由，不覆盖原记录。表单规则未知不能称格式符合。只做局部修改时停在该范围，不自动办理SW-06补正。

版本变化按“事实—范围/权利—选材/秘密—说明/表单—截图/渲染—关联旧审阅”追踪；只重做受影响项，但旧版未提及的行为不能默认为新版相同。保留旧记录，新稿关联待重审范围，不改旧签核版本号继续使用。需要正式补正时另核原通知、来源、逐项要求和期限，再读[补正方法](resources/follow-up.md)进入SW-06，不用本节模拟已完成程序。

交三份相互关联的成果：可编辑工作稿、来源/版本映射、内部问题及私有审计。技术负责人确认行为和版本；版权专业人员确认权属/规则；材料负责人确认清单与秘密处理；rendering接收当前稿和实际检查范围；workbench接收具体包/对象/用途/渠道的审批任务，内部审计不默认随正文外发。补证后重看关联条目，记录接受/拒绝依据及剩余问题。

## 交付前检查

- **来源与范围：** 软件/组件/版本、表达主张/排除和权利依据一致；未取得字节不报源码量，功能或Git作者不替代权属证据。
- **正文与证据：** 操作、成功/失败、环境按实际来源写；静态、运行记录及本次实跑分开，未见界面不造截图。
- **变化影响：** 核范围/权利、选材/秘密、说明/表单、渲染及旧审阅；只重做受影响项。
- **US适配：** 分开人类表达、作者/claimant、转让、AI披露、出版和秘密事实；旧表达不在主张内不等于从短程序完整交存中删去，来源或授权变化也可使同字节材料待重审。
- **复杂后续：** 旧版受让与本版新增表达分列，主体更名不混同转让/承受；逐通知项给替换正文，表达比较保留共同来源与独立创作反证，未知送达不算具体期限。程序及争议适用最新已核版本，不能把未授权公开自动写成未发表。
- **三类交付：** 正文候选、内部权利/选材/审计问题、行动条件分别说明。当前版本/范围、拟动作、对象、用途、渠道、批准角色及状态未知时汇总待核，并给权限负责人和恢复条件；源码处理权不替代交存/交付权。已有内部授权足够的修订继续完成。
