# 美国软件与控制技术：适格、功能限定和原始支持

用于美国实用专利的软件/控制技术内部分析、权项起草和申请后修改核稿。关联ANALYSIS-02—05、DRAFT-02/08、REVIEW-02及其AC，WP-05/10。返回[专利入口](../SKILL.md)；规则判断先读[US来源研究](../../../references/jurisdictions/us-control-evidence-20261101.md)，完整产物形态见[烘箱合成示范](us-control-example.md)。真实日期、答复和后续申请交dyz-procedure；图文显示交dyz-rendering。专题只形成有限开发候选，不宣称法域完整支持。

## 1. 固定权项、原始公开与证据的不同用途

先取实际被评权项、说明书及已有附图。区分研发汇编、原始申请、当前修改稿和后到运行材料；没有递交证据时，内部技术分析可以继续，申请后支持结论须标条件。原始权项也是原始公开的一部分，不能仅因说明书无同一句话就说原权项内容全是新增；反之，一个原有结果愿望并不自动披露实现它的结构、算法或整个范围。

按机制识别业务与技术路线，不按“智能控制”“处理器”标签分组。找实际输入含义、处理关系和输出用途：信用/收费结果只供人查看，还是测量经状态计算实际改变某个执行器；若改善计算机自身，还应解释数据结构、资源或运行关系的具体改变。不能为获得物理效果擅自给纯软件方案补传感器。

将原文设计、给定文献、实验记录和作者推演分别定位。以后到原件更正最初假设时，保留原假设、结论和影响；若一开始就看到所有阶段，称为阶段叙述示范，不能称盲释放验证。

## 2. 用实际限定完成101推理

按USCTL-01—03先理解权项整体及其合理最宽解释，再判断法定类别。USPTO Step 2A与Step 2B是对Alice/Mayo框架的审查实施，MPEP不是替代制定法和法院判例的法律。

- Step 2A Prong One：指出具体哪一限定可能记载数学概念、特定组织人类活动或可实际在头脑完成的过程，不把一切数据处理或软件都列为抽象。区分记载例外与仅涉及例外。
- Prong Two：在全部限定的有序组合中，解释例外如何被应用。对应说明书实际教导与权项必要步骤，判断是否改善技术、计算机功能或产生其他有意义实际应用。技术效果不必写成口号，但产生效果的步骤不能只在说明书中而从权项消失。不能在本步把额外要素以“常规”名义先删除。
- 仍指向例外时才做Step 2B：分析额外要素单独及组合是否显著更多。需要well-understood、routine、conventional判断时列事实基础，单篇出现过不自动证明广泛常用。inventive concept不直接等同102的新特征或103的非显而易见性。

应交连续的本案分析：实际权项是什么、可能的例外在哪里、其他限定如何工作、何处形成或未形成实际应用、剩余事实及结论。通用计算机更快处理合同排序通常不能仅凭自动化跨过101；特定控制的测量—状态—动作联系可能构成实际应用，但追加一句“控制设备”或一个无关物理步骤并不充分。也不要反向规定所有软件都须有物理执行器，计算机自身的具体改善另有分析路径。

## 3. 功能措辞用112三条线核查

| 审阅对象 | 实际问题和落地修订 |
| --- | --- |
| 112(a) written description | 原始公开是否让技术人员识别申请人占有当前整个组合和范围；同词出现、多个实施方式各有一块，不足以当然组合。先画支持关系，再选择已有方案的合理概括。 |
| 112(a) enablement | 所要求全部范围如何实施；输入、状态、触发、算法、接口及重要分支是否足够，剩余试验是否不当。与占有分别判断；不因没有量产或源码就自动否定，亦不把“任选算法达到结果”当教学。 |
| 112(b) definiteness | 动作主体、术语、边界、条件、数值及依赖是否清楚；“优化”“安全”“至少提高某百分比”若无对象/基准，先定位其范围不确定和事实不足。 |
| 112(f)解释 | 有means通常适用推定、无means通常不适用推定，都可依实际结构/动作和普通技术人员理解被推翻。检查nonce词、关联功能、是否有足够结构，不能只做字符串检查。 |

若112(f)适用，逐个列出完整功能、原说明书中明确关联的对应结构/算法及缺口；范围通常限于相应结构、材料或动作及等同物。专用计算功能一般不能只靠通用处理器支撑，算法可以用足够清楚的文字、公式或流程表述，不强制源码。一个模块承担几项功能，就逐项找对应关系，不用其中一项算法覆盖其余所有功能。缺对应结构可同时导致112(b)和112(a)问题。

若不适用112(f)，112(a)/(b)仍需独立过关。把module改名为unit、声明“不意图适用”、在前面加processor，都不能替代真实结构/步骤和全范围公开。权项改写可选择具体方法或有充分关系的装置，不硬凑三类别；英文所用范围、逻辑关系、单位及否定须与原文一一对应。

## 4. 102、103与101分别保留结论

逐篇比较完整限定及安排，记录原文位置、缺项、日期和材料完整性。合成给定文献只证明限定集合内的推理；没有真实检索就不写“未发现现有技术”。102不能拼多篇补缺成一篇公开，必要的释义/固有性旁证另说明其有限用途。

103按美国规则考虑现有技术内容、区别、普通技术水平和客观证据，写出最强组合理由及合理成功预期。特征都常见不等于组合必然显而易见；没有逐字建议也不能直接排除结合。结合理由可以来自相关问题、设计需求和合理常识，但关键技术缺项必须有有理有据的说明，不只标“常规选择”。

控制案例特别核查：另文献的信号、状态保留、丢包策略、复位方式和执行对象是否兼容；移植需要什么改变。对方没有建议你的做法，不代表明确反向教导。逐项比较替代解释和最强反证，并明确哪些待补检索或实验能改变判断。101整合实际应用的有利结论不能填补103或112的缺口，专利性也不能作为FTO意见。

## 5. 后到事实必须改变相关稿件

把新增材料分为原件边界证据、已有机制的解释/效果证据，以及新技术教导。新事实可以支持申请前研发稿，不可当然倒填已申请案；说明书/附图新增内容涉及132(a)，新权项缺原始描述依据涉及112(a)，适用程序由美国专业人员确认。原结果文字可证明原件确有该文字，但不证明后来设计已公开或旧范围可实施。

先保留旧稿，再交完整替换权项及用户所需核心说明，并更新支持映射、效果、101及102/103论证。效果下降或反证出现时，改成当前证据能证明的具体作用，不能只删内部风险清单而继续保留“零失效”“零超调”。数据来源、样本与重复范围不足时，明确结论只及于该记录；理论推演和实验各自标记。

有状态技术按原材料给定初态逐周期核输入、有效条件、计数/状态更新、输出和下一周期承接。无效周期是否保留状态、复位是否排队、边界是含等号还是不含，都可能改变方案。两个不同原因导致相同输出时分别解释，不把输出相同当算法等价。固定数值不足以支持任意范围，除非材料和专业依据给出概括基础。

## 6. 形成明确的内部交接

交付用户所需实际正文，以及单列的支持/反证意见、原件索引和后加研发内容。真实外发包按具体字节、版本、对象、用途、渠道及签核状态固定；内部原始数据、营销争议和新设计不默认随正文外发，也不得为了隔离而对受托专业审阅者隐瞒与审阅直接相关的事实，应另获相应用途许可后提供。

SMED是可选择的证据路径，非101必备或自动成功的机制（USCTL-04）。需要时先列拟证明争点、证人知识基础、客观材料、反证与程序阶段；实际声明由适格主体确认签署、专业人员审阅后按授权处理。不能把后到声明当作修补缺失原始技术的通行证。4月2026文书细节在本研究未取得，正式使用前补核，不仅照摘要套模板。

技术负责人核材料及控制机制，美国专业人员核范围、规则和英文形式，检索人员补关键日前证据，程序侧核实际案卷/阶段；共享层固定包和动作许可。未取得图时说明未出图/未渲染，不编图号。技术文字核查、真实测试、截图、专业签核、发送和官方结论分别报告。

交接不能把代理审阅、声明起草/签署、官方修改或声明提交、公开、另案和付款压成一句“各自授权”。逐动作列具体已存在文件/章节或尚未形成的专用包、接收对象、用途、渠道、实际有权批准角色、未执行状态和恢复条件；未知身份/账户如实留待责任人补齐。签署、审阅和提交的授权不能相互代用。
