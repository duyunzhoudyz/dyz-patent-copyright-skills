# 从原始事实到实际稿件的关系与修改支持复核

用于控制／软件方案起草、保义改写、参数修改和图文回查。它补足[核心方法](cn-core-method.md)的事实转换环节；不改变法域规则或专业责任。普通局部任务只记录影响当前结论的关系，不要求用户填写JSON或运行全生命周期。

## 先形成可核事实，再写正文

由执行者从获准材料形成“原句—解释—逐限制特征—实际正文／图位置”的支持链，资料已有的不重复追问。按以下顺序操作，不把工具记录当作事实本身：

1. **固定原句与载体。** 记录来源身份、版本、原句及可核位置。原件字节hash、抽取文本hash分别保留，并记提取方式、范围和二者联系，不要求两个hash相等。原件页／图、DOCX部件／段落、源码行与派生文本字符偏移分开；无可靠定位就记未定位，不估造页码。精确quote也须回核当前载体，乱码、漏图、错配抽取另记缺口。
2. **解释关系，不增事实。** 用人可审的文字说明句子约束哪个对象、动作、条件、量词、否定和时间范围；将明确记载与需推导的部分分开，保留相反解释及会改变结论的上下文。
3. **逐个列限制，再核组合。** 从当前完整权项或被审段逐句拆出动作主体／对象、关系、顺序、条件、参数和组合，每项回指原句及解释。一个特征有来源不代表其他限制已核；各特征分别有不代表同一实施方式中的组合有。
4. **对准真实产物。** 指向本次权项、说明书、摘要、实例、图元／图注或文件位置；直接重读这些产物，检查是否漏列限制、错认来源或只改了表。局部任务覆盖受影响句及必要上下文，完整任务核所声明的全部实际文本／图，未取得部分不得填成已查。

需要保留的事实内容如下：

| 记录 | 要保留的内容 | 避免的错误 |
| --- | --- | --- |
| 技术事实 | 对象、动作、状态、输入输出、量词、先后和作用时间 | 把常见实现补成原文事实 |
| 条件关系 | 条件到动作、动作到条件分别是什么；原文只说明哪一向 | “只有A才B”改成“A就必然B”；忽略“每次”等量词 |
| 未知与冲突 | 材料未给的分支、未观察到的行为、冲突的来源 | 无动作规则就默认保持；未知当成否定或自动选择一方 |
| 参数 | 原文参数域、关系和示例；产品事实；拟修改值及依据 | 示例升格为必要值；产品确认倒填原始申请 |
| 拟议设计 | 为补足机制提出的新方案、确认者和待验证条件 | 用“推论”“更安全”“更常见”让新行为混入已支持正文 |

先区分文档身份：固定原申请、其他技术来源、新产品事实、候选正文、内部分析。引用真实文字只能证明定位到了该句，不证明抽取解释正确或修改有原始支持；hash也不认证来源权利、原件真实性或正式提交身份。材料本身不完整时，完成已知部分，列出受影响的具体缺口；不要给缺件任务编齐，也不要对资料充分任务只交表格。

状态沿用explicit／inferred／unknown／proposal／conflicting。口头确认、新访谈或新代码可作为相应时间点的来源，但不能据此将旧申请未记载内容改成explicit。声称固有公开（inherent）时，单列候选推导、全部必要条件、反例及法域待核要求；不新增可自动支持原始修改的状态，不把待证结论反填为前提。机器原始支持检查仍只采用原申请中的明示前提；法域上可否接受相应解释另待专业审阅，不以“通常如此”或未找到反例代替。

## 把“谁记载了什么”核到论证正文

“本案具有某特征”和“某篇文献披露该特征”是两条不同的事实。逐篇记录该文献的对象、动作、条件及未知；不要因它与本案并列出现，就继承本案的用途、部件或效果。起点选择、组合理由、背景和总结中的归属断言，同样回到该篇原句；比较表正确不能替正文中的越界断言补依据。

例如，本案说明温度采样，资料甲只描述环形缓存：可以比较两者的已知机制，不能据此写“资料甲也用于温度采样”。如有外部依据或必然推导，单列该依据与推导条件；多篇组合的推论不改称单篇已有记载。资料未给的用途保持未知，不反过来断定用途不同，也不妨碍以已有共同机制给出有条件的起点理由。

机器辅助时，由执行者为单篇记载断言设置`assertions.attributed_document_id`并选择该篇事实。工具拒绝借另一文档的事实作该断言依据，即使其布尔公式能够推出；同一角色、同名术语或相同文本不合并来源身份。一般组合分析可以使用多来源，不设置单篇归属；其中“某篇已披露”的组成断言仍分别检查。文档归属匹配后，还须通过原有关系检查，不能用“来源正确”补足未知技术内容。

该字段和原子命题仍由执行者抽取，工具不会自动识别自然语言主语、错误映射或漏标的归属。没有工具时也逐句核来源，并保留实质缺口；未标字段的旧调用不自动获得来源归属检查。修改当前稿后重新回查，不将另一位置的正确句当作已撤回错误。

## 对每个关键限定做两种检查

1. **依据是否足够：** 在原文明确关系全部成立时，拟写关系是否仍可能不成立？如果能构造反例，拟写关系就不能被当作原文已经给出。反例是逻辑假设，不是新实施例或真实试验。
2. **改写是否等价：** 对声称保义的改写，反向也核对；仅原文能够推出改写，可能只是删弱了原限制。范围策略或候选限缩另作专业分析，不机械要求所有权项与整份原文逻辑等价。

先将原句翻成可审解释，再考虑有限形式化：“如果A则B”只给A→B；“只有A才B”只给B→A，未给的一向保持未知，不能补成充要条件。每个命题限定同一对象／事件和时间，量词、否定与例外不得省略；确认解释正确后，才讨论关系反例。

保义改句最后必须只看拟交付的替换句再做一次双向检查，暂不看自己的解释。对“只有A才B”，分别考虑A成立但B不发生、B发生但A不成立：原句允许前者、禁止后者。替换句若把前者也排除，仍然改了方向；解释中写对B→A不能补救正文中的“一旦A就B”“A后即B”。无法得到可靠等价改句时保留原句，不为显得有修改而换句式；检查只确认这些关系，不扩为法律结论。

正常、异常、恢复等待期分别核动作、对象和时间。禁止某动作不等于只禁止某实现路径；恢复控制须确认，不等于等待期间所有物理输出已经给定。区间内、等号、退化输入和多条约束同时成立时，核真正剩余的允许行为。材料未给的中间区间、异常或等待期动作不得默认保持、清零、复位、继续输出，也不能把“不知道发生什么”改成“什么也不做”。只阻塞该未知分支，仍保留其他已明示的正常条件。

删除／替换特征的论证保持其他条件不变；若其他条件已排除反例，不得声称仅删除该特征就导致该反例。语义无法可靠形式化时回到原句及逐句可审解释，记录未覆盖的量词、数值域或作用关系；继续完成有依据的文字，不能用一个不完整布尔模型代替技术或法律判断，也不能把“未找到反例”写成自然语言或法律支持已证明。

## 参数修改必须分别回答三个问题

| 问题 | 实际分析与产物 |
| --- | --- |
| 技术可实现性 | 已有设计／运行依据是否说明该配置可实现；未运行不写成实测 |
| 实现覆盖 | 该产品实现的其他条件、关系和动作是否满足当前候选范围；数值相同不是全部判断 |
| 原始修改支持 | 对拟具体化的数值／范围，分别核原文参数域、作用与效果、组合条件及具体取值的确定依据；说明何种原文和适用规则条件下可考虑该修改，何种新增信息会使该路线缺依据 |

三项逐一记录已知依据、条件性判断和未决问题，不能把最后一项用前两项替代。原始修改支持至少展开四个考量：

1. **原文参数域：** 核上下界、开闭端点、单位、离散／连续、等号和参数耦合；数学上落在区间只是第一步。
2. **作用与效果：** 核拟值是否改变工作区间、触发分支或效果条件；新试验能够补充什么判断，不等于它能倒填原始公开。
3. **组合条件：** 拟值原来与哪些对象、步骤、其他参数共同披露；分别出现的取值不自动形成可修改的组合。
4. **具体取值的确定依据：** 原申请是否给出该值、可明确得到该值的关系或选取依据；分别说明可考虑修改的条件、需要新设计选择等会使支持不足的相反情形及待核规则。

原文没有逐字写某值，不自动等于该具体化绝无可能；一般参数涵盖该数的数学事实，也不自动使申请后修改成立。交条件性分析、相反情形、需要补核的具体原文／规则及可继续使用的参数稿，专业可接受性仍由相应法域审阅。不能只写“参数保留、具体值放产品栏”就算完成用户要求的修改评估。

## 回到实际正文和图

在权项、说明书、摘要、实例、图元／图注和最终输出中，逐处标出新增／改写的关键限定并关联事实记录。每处都核条件方向、对象、量词、否定、时间和参数；不能在内部分析写对，正文或图又补错。禁令的对象与触发范围同样必须保留：“故障时禁止新动作”不能解释成“故障时只禁止由某种输入引起的新动作”。

未给事实应留在内部缺口，不靠“例如”“本实施方式不作限定”“凡能实现均可”写成确定结构或实施步骤。连接端口、安装位置、驱动部件、复位方式、解除动作或信号形式若不是原材料明示／可核推导，就不能进入已支持实施方式或摘要；确需提出新设计时独立标proposal，不借工作稿身份混入原方案。

交付前按“确定有依据／尚待确认”分流每一处拟写内容，并执行在正文中删除或保留的决定。标为inferred且推导仍有争议、待技术确认或缺组合依据的内容留在内部问题单，不先放入权项、实施方式或摘要再用脚注免责。未知处理写在内部范围说明；权项只限定已知技术关系，不塞入“本装置在此情形的工作方式未限定”这类审稿说明。删去无依据内容后，以剩余正文独立复核支持，不以原来较完整的表或预想修订替代。

保持内部回查表与候选正文分离。有限分析可使用[本地关系核对工具与示例](tools.md#事实关系与参数修改复核)；最终交付另须通过[实际正文门禁](tools.md#最终正文验收门禁)，后者从真实字符解析，不接受正确公式替代错误正文。2.0按类型保存成员、用途、比较、能力、禁止／恢复及条件方向，保留方案范围、原句区间和全文覆盖账本；概括表述也要回到同一范围内的具体关系。缺用途、数量或组合依据应按诊断回源补证，不能靠通用同义词或拆角色原子放行。由执行者生成机器记录，不让用户重做专业抽取。没有工具时可完成内部分析、正文和回查并标未检查，但不能把工作稿升级为门禁通过的最终交付。

机器检查的输入身份如下：

- `original`：调用者提供的原始申请／固定原文；真实性和是否正式提交另核。
- `source`：其他给定技术材料；不能作为原申请支持自动继承。
- `product`：新产品／配置事实；不补足旧申请原文。
- `candidate`：本次实际拟交正文，按当前UTF-8文本绑定hash和字符区间。
- `internal`：内部理由、条件分析、未知和新设计提议。

关系的原子命题要说明含义和作用域，同名动作在不同时间／对象上不可默默合并。仅明示且适用于本次模型的事实进入推理；推断、未知、提议、冲突以及待证固有公开不当作已证实前提。每条关键正文关系有来源与稿件位置；所有候选文本区域须登记技术检查或说明为何属于标题等上下文。映射完成后另做一遍直接逐文本审阅，独立于映射表找遗漏限制、组合缺口、错文献归属以及正文／图与内部记录不一致。这个分类和覆盖仍需人工／执行者复核，程序不会自动发现所有隐藏限定；执行者自查也不冒称独立专业验收。

有限工具在实际调用、输入符合其契约且相关分支已执行时，可报告满足原前提但违反拟写关系的赋值，或前提冲突、无法确定、缺修改分析、未映射正文及版本不符；`checked`只表示报告所列记录与范围的检查完成。它不理解自然语言、不验证命题抽取、不证明一般数值域、不判断充分公开／修改合法，也不替代真实试验、专业签核或出口门禁。模型评分与作者判断仍须分列。

检查报告逐项写对象／版本、实际输入与调用范围、执行结果、未执行／部分／不适用及原因、产物影响和补核责任。无正文绑定的分析结果不称完整稿件核查；正文扫描、来源绑定、有限关系核对、参数评估、图义、视觉和专业审阅不能合成一个笼统通过。机器记录正确但实际正文不同，仍按正文问题处理；不得只补内部解释或resolution就声称候选已修正。接口未提供或本次未调用的检查明确未执行；仅轻量扫描成功不提升为完整保真，research_example的完整fidelity限制按[工具契约](tools.md)保留。必要检查缺失或存在严重支持缺口时可交清楚标识的工作稿，不能升级为已检查候选。

完整合成示范见[记录器正文候选](fidelity-recorder-draft.md)和[独立内部分析及参数修改评估](fidelity-recorder-notes.md)；它们是作者构造的开发案例，不是独立模型或专业验收。所需DOCX装配与回读入口见[文件工具说明](../../dyz-rendering/resources/tools.md#可选事实关系与实际正文绑定)。

发生变更后保留旧稿，更新事实／关系、三项参数分析、正文／图和导出文件，重新绑定受影响检查；旧hash或同名文件不能复活旧审阅。源材料、权项、图、规则、用途或范围改变时分别核受影响结论；已记录解释、接受带风险稿、补足证据和实际文本已修订分开，普通技术确认不冒充专业签核。

## 来源读取范围与合计

把“读过什么”也作为需保真的事实：按文献、版本、介质、操作及事件分别记录页／段／图范围，区分本轮直接记录与既有研究转述。合计归到明确列出的组合，不能给单篇换上组合总数，也不把XML通读、PDF已渲染或同族另一版本当本篇全页目视。

需要陈述具体读取量时，按[读取范围工具](../../dyz-workbench/resources/reading-scope.md)先核记录，再生成单篇与合计的Word文字并严格回验。有限检查不认证记录或自由文字解释；未纳入投影的正文、摘要和内部说明仍须反查来源归属。
