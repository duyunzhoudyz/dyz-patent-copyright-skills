# CN静态外观：从几何事实到可审多视图

用于CN申请前静态立体产品的整体/局部范围选择、图组起草和技术一致性核稿；关联DRAFT-07、FIG-04、REVIEW-03及其AC、WP-10。先读[本次官方依据](../../../references/jurisdictions/cn-design-evidence-20261101.md)核目标时点；完整实例见[读卡器示范](design-views-example.md)，可编辑线稿见[图源](design-views.svg)。这里提供开发方法，不代表已经通过真实外观专业或官方图式验收。动态GUI、成套设计、海牙及其他地区须另建事实与规则适配。

## 1. 固定材料、阶段与最少缺口

先确定用户要整体方案、局部方案、简要说明、制图还是核稿，材料是研发设计、CAD导出、实物照片还是已提交图片。记录产品/用途、来源版本、坐标基准、观察方向、色彩及省略意图；没有公开日或申请日就分别写未提供，不能默认未公开或尚未申请。合成资料明确合成，不把建模结果冒充实物测量。

将每个外表面、特征及连接边写成事实ID，至少说明位置、轮廓、凸起/凹陷/共面、透明性和可见状态。几何只应足以决定外观，不为完整感补内部机构。只有正面照片时不能镜像出背面；有完整获准模型时可推导视图，并记录所用投影与推导身份。

遇到冲突并列原图、文字与对应坐标，说明哪几面或哪份正文无法确定；不自行判较新/较美观者正确。给技术负责人一个能回答的定向问题，同时继续不受影响部分。收到确认后形成新事实版本，保留旧资料、回答与影响范围。后到确认只解决内部事实，不自动成为申请日支持。

## 2. 先选范围，再选线型

比较有材料支持的路线。整体设计包括整件产品的视觉组合；局部设计把特定区域作为请求保护对象，同时须表示它在整体中的位置和比例。不能简单把实线越少说成保护越强，不能靠简要说明排除仍用实线表示的结构。

每个候选说明：稳定识别特征是什么、供应变型是什么、排除会失去什么、与接近设计的共通部分是什么。本案上壳楔形和表面分区稳定，底座可换，因此选完整上壳局部；代价是底座与底面垫片外观不在请求保护部分内，且不能据此覆盖任意位置/比例的上壳。整体路线能把底座组合纳入，但更依赖具体底座；只取顶面矩形会丢失楔体与左右特征，还须核纯图案局部等客体边界。

按本次指南第一部分第三章4.4核：局部是否形成相对独立区域或完整设计单元；名称是否包含局部及整体；整体背景是否足够；含立体形状时是否有清楚显示该局部的立体图。无明确分界才考虑点划线，本案已有z=6实体接缝，不另造任意截线。最终适格、明显区别和权利范围仍须相应专业审阅。

## 3. 建立投影和可见性账本

把产品固定在同一坐标中，再定义各观察方向及图面水平/向上轴。示范坐标x向右、y向后、z向上；六个正投影的毫米换算比例一致，各图只平移排版，不独立拉伸。避免“左图放在左边”代替左视方向定义。

| 图名 | 观察侧 | 图面(u,v向上) |
| --- | --- | --- |
| 主视图 | y负侧 | (x,z) |
| 后视图 | y正侧 | (-x,z) |
| 左视图 | x负侧 | (-y,z) |
| 右视图 | x正侧 | (y,z) |
| 俯视图 | z正侧 | (x,y) |
| 仰视图 | z负侧 | (x,-y) |

这些是示范的明确制图约定，不是要求所有产品以相同面作主视。主视选择应结合使用时朝向消费者的面或整体设计表达。图名放相应图下方，避免名称和几何来自不同版本。

投影后另查遮挡。示范不透明凸体按表面外法线与观察者方向向量的点积判断可见面；凹槽、穿孔、多层和透明件不能套此简化。正面可见升高斜顶，后面却被高面遮挡；侧面只见所属特征，底面共面垫片不从侧视凸出。前右上轴测只显示顶、前、右，不画左圆片和底垫。

为每面登记轮廓、可见特征、遮挡特征、对应图及数值范围。循环核对至少包括：前/后同宽、侧视同深、最高/最低位置、同一特征投影前后是否一致。数值推导能发现方向和位置错误，仍不能证明图线清晰或官方接受。

## 4. 生成可编辑图组并检查范围

同一数据源生成全部视图，每图独立组，轮廓、嵌片和标签可单独编辑。保留生成方法、实际输入与源文件哈希；后续手工修改应回到模型或记录偏离，不能让图组悄悄分叉。图源不是照片，也不是官方上传包。

局部路线用实线表示拟保护部分，用虚线表示本视图可见的其他部分。被不透明实体遮挡的部分无需透出隐藏线；“不保护”与“不可见”是两个维度。本案仰视只见底座和垫片，全部虚线；俯视只有上壳及顶面分区。上下实体共享接缝在相应侧面作为上壳外缘用实线，底座其他边虚线；同一投影边只输出一次，避免实虚叠线。该具体表示是案例推导，须专业审阅。

图面删除研发尺寸、中心线、阴影、引线和内部编号；必要注释与图名分开。内部审阅图板可以有清楚的草稿标识，正式单图输出前须按实际渠道再核图幅、清晰度和允许内容。一般SVG不等于CAD验证或2026电子申请XML转换验证。

## 5. 写完整说明，不让说明替图

简要说明给出实际产品名称、用途、设计要点、指定图及必要的色彩/省略/局部表达。局部名称带所在整体；指定图应包含拟保护局部，不能指定一幅全是非保护部分的图。表述与最终实虚线逐项对照，不把范围讨论、风险记录和授权请求塞入拟申请正文。

本案可写用途为读卡器上壳，用于桌面读卡器的外部覆盖；不用“高速、安全、自动识别”等性能承诺，不写内部线圈。实际未省略就不写省略理由；黑线白底是图示方式，不自动构成请求保护色彩。已在图中表达的局部也可作简洁线型说明，但不能用文字补出缺失面或扩大图示范围。

同时交内部范围理由和最强反证。比较共通轮廓、大块分区、差异位置以及常见观察角下的视觉影响；不能用发明技术效果论证取代外观评价。比较材料没有公开证据或真实检索时分别标明，原创建模与未命中都不能证明可授权。

## 6. 修订、验证和具体交接

逐图记录旧名称/几何、确认来源、新对应和实际变化；正文、范围清单、指定图、图文件及包清单一同检查。无变化项说明为何不变；受影响旧审阅置为待重审，恢复旧字节不自动恢复签核。申请前设计完善与申请后修改分流：若发现已提交，先取得原始图片、通知和日期，交PROC及CN专业人员核第33条和程序条件，不凭后到技术说明补原申请。

验证分四账：数值几何/结构检查、实际PNG视觉检查、专业图式与范围审阅、官方格式/提交结果。先生成并冻结图源，再实际渲染检查裁切、线型、图名、形状和文字；未运行就写未执行。此示范由标准库脚本作前一层，实际视觉由根流程另取同版PNG，不拿XML解析替视觉或专业通过。

交接包绑定具体版本、文件范围、对象、用途、渠道、有权人和状态。拟包也须列文件名/版本、选用视图名或组ID及文字界限，不能只写“配合所需图”；未导出与未获批分别记录。内部包可含比较/问题，工厂包不默认带内部风险；申请包另核身份、委托、专业签核和电子转换。技术确认不扩为外发；缺口只限制对应行动，已授权内部稿继续完成。
