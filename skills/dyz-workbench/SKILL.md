# DYZ 共享工作台

## 按任务加载

下文处理问诊、分流和续接；用户已明确专业和单步范围时，直接进入路由表对应Skill。

只有安装工具、调用CLI/版本记录、生成固定预览或运行合成披露演练时，才读[共享工具说明](resources/tools.md)对应章节；依赖Python 3.11标准库与完整tools包。文字流程不要求用户先填JSON，也不把工具调用作为交付每份文字稿的前提。

关联CORE-01—07、REVIEW-07、LIFE-01/03/04及相应AC/DG-01—20，WP-01/02/04/10。真实出口与身份认证不由本Skill说明实现。

## 从用户请求开始

先完成下面的任务入口，不要求用户认识CORE编号或预填JSON。用户只要核稿、单位检查或一份说明时，只处理该步；明确专业的单一任务可直接交对应技能，不强制建立全部共享记录。

这里的文字入口可以整理非敏感任务描述、已获准事实和合成材料；[工具资源](resources/tools.md)中的Python CLI及审批演练仍仅支持合成资料。敏感原件不得先上传再补授权，任何工作流说明都不是宿主隔离证明。

### 1. 定义本次交付，再问最少问题

先用一句话复述具体交付：咨询意见、内部工作稿、修改建议、审阅清单或正式动作准备，并注明不做的动作。只在答案改变当前步骤时追问；能从获准材料确定的事实不要重问。

| 需要辨明的事项 | 先从哪里看 | 缺失时怎样处理 |
| --- | --- | --- |
| 本次目标与范围 | 用户原话、明确选中的段落或材料清单 | “帮我看看”不能直接扩大为三业务全链；先问希望得到哪种结果 |
| 业务与阶段 | 技术交底/权项、源码/登记、条款/标准提案等材料性质 | 多业务分别建任务；只是用词含“标准”不当然属于标准编制 |
| 地区/组织与类型 | 明确委托、通知、项目说明 | 缺失不阻止事实整理；涉及期限、格式或实质规则时先补，不默认中国规则适用于全球 |
| 材料版本和公开情况 | 清单、版本标记、实际公开/提交记录 | 编号或口头说“申请了”不是实际支持；拟公开问题转procedure核查 |
| 时间与预算 | 用户明确的截止需求及授权范围 | 区分工作期望和法律期限；不得为了“赶时间”猜期限或开启付费服务 |
| 权限和数据路径 | 材料类别、用途、授权依据和宿主环境 | 仅问非敏感元信息；路径/权限未明时停止读取、索引和上传敏感正文 |

不要一次索取所有合同、源码、证件和技术全文。先问当前步骤必须的事实，给出为什么需要；身份材料不用于一般任务路由。

### 2. 先排材料，再读获准正文

1. 列出材料名/版本、提供者声明的性质、用途、是否已获准本次处理、缺页或未知状态；没有实际读到的内容标“未读取”。
2. 先读本次任务的主材料，再读解释其版本或冲突所需的旁证。保留原件及具体章节/行/页定位；无法读取或OCR不确定则回源核实，不补齐缺字。
3. 每条关键陈述区分“材料记载”“用户陈述”“Agent推断”“待确认假设”。事实相互冲突时保留两方与来源，不用更顺畅的一种表述覆盖。
4. 只把本次确需共享、且接收业务用途获准的证据交给其他技能。可共享同一证据引用，不共享同一专业通过状态。

### 读取范围与差异优先

先由任务和目录定位适用方法章节，再读当前主材料及解释冲突所需的原文。示范、历史记录、其他专题和工具参数按本步需要展开；正文起草、范围论证与修改联动要求的方法不能被摘要代替。跨章节条件或引用影响判断时连同依赖读齐，只有目录、检索命中或摘要时明确其覆盖。

- 首次读取保存来源／版本、实际章节或行列范围及未读部分；同版已读且仍在上下文的内容直接复用，不为确认重复全读。
- 更新先列旧／新版本、变化位置、异常和未解释项，再读变化原文、必要上下文及依赖条款。路径、文件名、hash和“无差异”均不证明全文阅读或专业等价。
- 长输出先定位问题ID、字段、书签或XML位置；完整报告仍保留在获准目录，按定位补读。不能把省略片段写成已检查；源变化时原读取覆盖只属于旧版。
- 每项补证写原问题ID、所缺依据、确认角色、阻塞结论及恢复后重查范围。正文有据部分继续完成，收到材料、接受结论和批准行动分开。

### 3. 路由与责任

| 用户实际需要 | 主处理技能 | 交接前的最小产物 |
| --- | --- | --- |
| 技术挖掘、检索策略、交底、权项、图示需求和核稿 | [dyz-patent](../dyz-patent/SKILL.md) | 目标、获准技术材料、版本、已知疑点及拟适配地区 |
| 拟公开、申请支持/日期、通知、程序和专利争议 | [dyz-procedure](../dyz-procedure/SKILL.md) | 具体事件、原件/缺件、时点来源、内容版本及责任人 |
| 软件范围、权利、源码材料、使用/设计说明和补正 | [dyz-software](../dyz-software/SKILL.md) | 软件/组件/版本、材料权限、目标地区与主体事实 |
| 标准研究、范围、条款、验证计划、意见和修订 | [dyz-standards](../dyz-standards/SKILL.md) | 组织/类型/阶段、需求、来源权限与技术事实 |
| 显示、图文对应、分页、裁切和检查证据 | [dyz-rendering](../dyz-rendering/SKILL.md) | 已冻结或明确标为工作稿的源、用途、格式与待查问题 |

技术负责人确认实现、参数、效果与材料版本；对应专业审阅者确认法律适用、权利、标准方法和程序；有权主体批准具体行动。Agent负责有依据的提取、比较、工作意见、起草与自查，不把“建议请专家审核”当作未完成分析的替代。每个升级事项都写具体争点、已有依据、所缺依据和接收人角色。

### 4. 任务简报与部分推进

每个任务简报包含：业务/目标、允许与禁止动作、适配条件、输入版本及来源、已知事实、待确认事项（阻塞哪一步/谁确认）、预期产物、下一接收者。对本次不需要的字段写不适用理由，不编造值。

缺权限：停止相关材料接入；缺规则：继续事实整理但暂停规则结论；缺技术事实：交可写部分和待问表；缺渲染：交明确静态稿。任何暂停都说明恢复所需材料及恢复后需重查的步骤，不把一个缺口扩大为所有业务不能工作。

### 4A. 中断续接、答复合并与接收确认

续接先读用户本次目标，再读已有交接简报、已交产物版本、问题ID、允许动作和未完成记录；旧待办不是新行动授权。只加载当前需要且仍获准的材料，缺快照/来源时保留未知，不从上一轮总结补造原件。没有保存记录就据已见材料重建有限摘要，标明其覆盖，不冒充恢复了全部历史。

1. 将新答复挂到原问题ID、来源/确认者与版本；分别记已确认、部分回答、冲突、未回答。已有明确答案不重问；新答复只覆盖指明范围，阈值确认不自动证明所有产品采用该值。
2. 对照版本/语义、来源、权限、接收者、用途及规则变化；同字节副本或恢复旧文本不证明同一来源、权限仍有效或旧审阅复活。建立“变化—依赖产物—旧结论影响—重做步骤—确认者”表；只重做受影响链，无影响项写依据，不重跑所有业务。
3. 续接摘要包含本次目标、已完成文字、实际检查、待专业审阅、阻塞和下一个最小动作；正文、对外候选与内部问题/审计分离。权限过期或对象变化时先重核对应用途，其他获准内部分析可继续。
4. 内部交接便笺列交付版本/范围、问题ID、接收角色、所需确认及恢复条件；便笺实际列“正文候选、内部风险/问题单、禁止随包或尚未核对材料”三栏及各自用途，缺原件写未核，不因全部仍在内部而省略分流；“拟交接”“已发送”“接收者确认收到”“接受业务结论”“有权批准行动”分开。有实际记录才升级状态，不因发出便笺或文件存在就标已接收。接收方发现版本/范围不符则保留退回原因并重开对应问题。
5. 接到确认后检查其权限、版本和覆盖，再关闭相应待办；部分确认不关闭整包。外发/正式动作仍需独立授权及实际回执，unknown先核实，不自动重试。已有CORE-06/LIFE-03/04可辅助关联，未运行时交手工依赖表，不填工具通过。

**合成续接例。** D1阈值4，D2获准答复确认改7；P1支持意见与T1条款依赖D1，S1是否采用新设计未知，旧H拟交乙无收件记录。摘要写“D2参数确认，P/T关联支持与验证待重审；S仅核适用性，不立即改成7”。便笺给专利/标准角色核受影响内容，给软件技术负责人问D2是否进入S1，不再问4到7；给材料负责人核H实际接收。若新增收件人丙且授权仅乙已过期，暂停相应传递；内部稿继续，但不能把D1副本、旧审批或同名文件作为新授权。


### 5. 三个入口示范（均为合成，不是真实案件）

**多业务：** 用户说“控制器项目要专利、管理软件登记和标准提案，先安排任务”。已有设计v2、软件v3、范围草案v1；地区/组织未知，无实际申请记录。先交三份简报，不写正文：专利侧整理技术/公开事实并准备交底，软件侧先查范围/主体/贡献再选材，标准侧先查组织/范围/来源再写条款。共享设计来源可关联，但标准公开必须另查实际申请支持；不让登记状态或申请编号替代。优先询问拟交付地区/组织、公开事件和合作权利依据；没有答复也可列材料清单，不编造结论。

**单步核稿：** 用户只查单位和图号。正文“20 ms/图2”，表格“20 s”，仅有图1。输出两条冲突及位置，向技术负责人核实周期、向稿件负责人确认图号对应；不猜哪份正确、不检索、不重新设计权项。

**权限不足：** 用户尚未上传客户方案和证件，宿主路径及处理授权未知。不要索取全量上传；只询问任务种类、材料类别及目标用途，列出需核实的客户授权和宿主数据路径。恢复条件是对应授权/环境依据落实后，只读取本步所需材料；其他不含敏感事实的流程咨询可以继续。

### 6. 进入工具前的检查

先得到专业步骤产生的事实和决定，再按[工具资源](resources/tools.md)中的字段契约转换为工具输入；不得从API必填项倒推或虚构事实。当前CLI要求synthetic，真实材料不能改标签绕过。工具不可用时可以交文字草稿/检查计划，精确运算、版本工具记录及外部观察如实标未执行。用户需要正式动作时，只准备明确的审批/交接材料，另行确认具体授权，不自动执行。

## 专题适配与支持证据登记

适配不是给现有稿换地区标签。先按本次请求建立“能力/主业务—地区或组织—权利/标准类型—领域—阶段—材料版本—规则版本—用途权限”的任务卡；无关轴说明不适用，未核轴保持未知。规则来源索引只指向待研究材料，不是已经生效且可处理的规则包。真实来源须先核取得/模型处理/翻译/再分发权限，再由对应专业核其版本、适用对象、生效和例外；本轮不联网时只列缺口，不编当前法律。

### 从来源到局部恢复

1. 阅读获准需求、现有任务卡及规则变更摘要，先确认变化是什么、影响谁；不因为有新版本就重做全部业务，也不把未核实摘要当完整新规。
2. 建任务×适配×证据表，分列写作状态、实际Agent任务结果、专业审阅、自动发现/安装与正式行动。每条任务结果绑定案例、Skill/输入/规则版本和实际回答/评价；映射有章节不等于案例已过，机器检查通过不补未执行的专业任务。
3. 按依赖定位受影响稿、验证、审阅及行动权限；历史保留，新版缺证标待复验。某地区/组织案例通过不能推广到其他组合、其他版本或全部83能力；不适用须有本项依据，不能用未执行冒充不适用。
4. 实际交付更新后的状态表和内部便笺；便笺含正文候选、内部风险/私有审计、未核或禁止随包材料三栏及各自用途、接收角色和恢复条件。新接收者仅有正文权时不附风险/审计，也不先发送再补权；接收/认可/行动批准仍分开记录。
5. 规则与期限由原业务解释：专利PROC、软件SW-06、标准STD-09/11，LIFE-01只汇总依据和提醒。审阅人资格、保密安排及可能的保密特权须具体核证，不能因律师/模型参与即推定受保护。补件只关闭其实际覆盖的条目，不使旧签核复活。

**合成例。** 组织Z从R0改R1，变更仅影响标准条款评议；同源软件和专利无相关规则/内容变化。表中标准旧R0案例保留历史通过，R1任务未执行；R1结构检查通过独立一栏，专业审阅仍未执行。其他两业务记本次未见依赖变化，不新增“本轮通过”。便笺候选：“请标准责任人核R1适用及受影响意见/待审包，完成同版任务和必要人审后更新对应状态；仅正文拟交指定角色，内部风险/审计留存，接收尚待确认。”

完整能力查漏采用逐ID的主工作流/章节/产物/状态，不新建能力编号；索引属于开发写作导航，不是运行依赖或专业支持注册表。只有原则/接口的分支仍列待深化；当前工具的synthetic_helper_only不因新增方法文字升级。

## 交付前检查

- **范围：** 交付对应用户当前目标，三业务各自的状态、版本与专业责任保持独立；旧待办不扩大本次授权。
- **事实：** 已读、未读、冲突及推断分开，缺件只阻止受影响步骤，不重问已有答案。
- **续接：** 变化落实到依赖产物、受影响审核与恢复责任；无关业务不重做，同字节不自动恢复签核。
- **交付：** 正文候选、内部问题/审计、禁止随包或尚未核对材料及其用途分开；拟交接、实际发送、接收、认可结论和批准行动分别记录。按现有有效授权推进，新的具体外发条件未知才保留待核。
