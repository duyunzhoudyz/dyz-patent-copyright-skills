## 1. 先保留构建依据，再核字节

在已核来源的完整源目录或可信完整包根运行。下面路径是示例，目标父目录须存在、目标须不存在；命令不注册宿主、不安装系统依赖。

```powershell
python -m tools.bundle --destination D:/dyz-review-package
$dyzExpectedManifestSha = (Get-FileHash -LiteralPath D:/dyz-review-package/bundle-manifest.json -Algorithm SHA256).Hash.ToLowerInvariant()
python -B -m tools.bundle --verify D:/dyz-review-package --manifest-sha256 $dyzExpectedManifestSha
```

首次可信构建后，把清单SHA-256、来源／版本和构建时间保存在包外的项目记录中。续接时使用该记录，不从可能已被修改的包重算“预期”。对于他人提供的包，先用已核来源的校验器核对，不先执行对方包内的Python代码来证明它可信。即使哈希匹配，也只绑定给定字节，不认证提供者、许可或专业结论。

校验器可从可信源目录调用，也可在明确可信的完整包内调用。异目录时可直接用可信校验器的绝对路径：

```powershell
python -B D:/dyz-trusted-source/tools/bundle.py --verify D:/dyz-review-package --manifest-sha256 $dyzExpectedManifestSha
```

不带`--manifest-sha256`时仍核每个列入源的大小和SHA-256，但结果为`manifest_internal_consistency_only`。文件与清单被一起改写可能仍内部一致；这不能替代包外依据。`expected_manifest_hash_matched`也只表示与调用者提供的预期相同，不推定该预期的权威性。

## 2. 读懂结果和恢复路径

成功退出0，输出JSON中的`source_files`、`listed_bytes`和`manifest_sha256`描述本次实际清单。只读取校验器内置的同版固定源清单；全部清单路径／结构合格后才读源文件。不执行被核业务源码，不递归枚举或读取运行输出、private或其他未列路径。因此成功不表示整个目录没有其他文件，更不表示新增文件可以发布。命令中的`-B`避免Python加载校验器时另写字节码缓存，尤其适用于从待核包本身运行；函数校验过程只读，不自动清理既有缓存。

校验清单结构、完整当前版本文件数／顺序、字节数和SHA-256；拒绝重复JSON键、过大清单、缺件、同长度内容变化、陌生／重复／越界路径及列入路径中的符号链接或reparse point。错误退出2，stderr为`bundle_rejected`；I/O失败退出3，stderr为`bundle_io_failed`，不输出原文或私有路径。校验不写修复文件、不覆盖原件。

被拒绝时保留现状和原可信记录，先分清包版本不匹配、缺件、权限／路径问题或实际变化。不要编辑清单以掩盖变化，不把当前文件重新算出的哈希当旧预期，也不要覆盖旧包。需要重新构建时选不存在的新目标，另记新依据；已有项目事实、产物和审核按影响决定重做，旧记录保留。版本清单不同时须使用对应可信校验器和来源，不把本校验器拒绝旧清单写成旧版原文件损坏。当前源清单以本次随附manifest及同版校验器为准；仅在包外预期与实际清单SHA-256都精确等于r21的`5074f7446cf2b246269e80d22a3b7589d25e69850f30c263753cfb184af17708`时，校验器允许原249路径布局，返回`r21_externally_pinned`；不接受任意旧249清单降级。 r22元数据候选的原250路径仅在包外预期和实际清单hash均为`3cbaa33bec1c9a554bef04567dbde12ee9f70e15b8d176e13ae938d729699dba`时返回`r22_metadata_externally_pinned`；任意250清单仍拒绝。

校验期间目录和父目录须由调用者保护不被并发替换；这不是恶意进程隔离、秘密扫描或签名验证。未知文件保持未核，当前校验器不检查工作区所有出口。

**此处基线不是默认全局发现。** 三个进程都显式`features.plugins=false`，只转发操作系统环境白名单，并设置本次自有启动值。version3对该固定二进制使用`CODEX_INTERNAL_APP_SERVER_REMOTE_CONTROL_DISABLED=1`，避免默认从`Unknown`解析持久化远程控制状态；这是版本绑定的内部标记，没有跨版本保证。工具实际核每个原生进程的已知JSON启动事件为`Disabled`；状态缺失或非Disabled、日志超长、读取异常均不能通过。只保存状态、计数和hash，不保存服务器名、安装ID、端点或日志正文；其他启动告警只计字节与hash。`LOG_FORMAT`及日志过滤由本入口固定，不继承父会话控制值。

各进程另有一份本地原创合成模型元数据，合成占位不是实际模型或厂商指令，不能用于模型案件。原五秒退出0及两路读流结束的门槛不变；成功才删除本次确切临时文件／目录。失败保留目录、PID、已完成RPC及退出信息，不写成功profile、不杀进程或自动重试。原生阶段错误的`observations.phase`定位baseline／scoped／baseline_recheck，`completed_processes`保留先前已结束进程，`failed_process`列本次失败；其中完整argv替换为`argv_sha256`及数量。PID可能重用，必须结合持有的进程句柄或创建时间／可执行文件确认，不能按旧PID清理其他任务。

当前生命周期另带`native_process_counters`，在`spawn`、`stdin_closed`及`after_wait`三处直接读取本次`Popen`的Win32句柄，记PID、`creation_filetime_100ns`、内核／用户CPU时间和句柄计数，不按PID另开进程。三处创建时间与PID必须一致，`native_identity_verified`才为真；初始身份不可观察时不发元数据请求，缺失或不一致均拒绝成功profile。存活时退出时间未定义，因此不输出该字段；句柄计数读取失败明示`unavailable`及错误码，不能填0。这些计数不证明等待原因，也不改变原五秒门槛。实现只用Python标准库直接调用Win32，不加载开发用的PowerShell／.NET线程采集器，不取栈、对象名或令牌，不调用权限调整。

仅当全部检查成功才退出0，profile状态为`local_process_metadata_verified`，当前字段版本为3。`baseline_counts`与`scoped_counts`列真实数量，其他目录错误仍计入；早期version2源观察为732／729→732／6→原基线，不迁为version3通过。version3一次独立单阶段取证实际见732发现／6启用、13项其他错误、六安装路径描述精确匹配；这只验证该次选择和计时，不是原三步或重复稳定性验收。

`metadata_bootstrap_environment`只说明元数据探针的启动环境；`process_config_arguments`只是选择参数，`thread_config_candidate`仍是未启动验证的线程候选，合起来也不是完整模型宿主。合成目录不放入可复用模型设置。真正模型客户端仍须提供适用的模型目录、权限、数据路径和实际业务工具；本地case接口不由此工具自动注入。
